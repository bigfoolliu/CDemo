# 用 C 实现教学 CPU 模拟器（CPU emulator）

这个案例用一个很小的自定义指令集，展示 CPU 模拟最核心的“取指 → 解码 → 执行”。机器码是数据，宿主 C 程序读取这些数据并更新模拟寄存器和内存。它不是 RISC-V 或 x86 模拟器，不能运行这些架构的二进制程序。

## 1. 运行与调试

在仓库根目录执行：

```sh
make cpu                         # 构建并运行两个案例
./build/cpu/demo --trace          # 终端与文件同时显示逐指令状态
less logs/cpu/trace.log           # 回看完整过程
make test-cpu                    # 运行指令和边界断言
make sanitize-cpu                # 地址与未定义行为消毒器
make compile-commands            # 更新 clangd 代码提示
make debug                       # 构建独立调试程序
```

默认输出为：

```text
=== 累加 1..10 ===
OUT=55
正常停止：55 条指令
=== 内存写入与读回 ===
OUT=55
正常停止：6 条指令
```

VS Code 选择 `C: 教学 CPU`，在 `cpu_step` 内设置断点，按 F5。观察 `cpu->pc`、`cpu->registers`、`step.bytes` 和 `operand`，逐行查看取指、校验与执行。配置默认带 `--trace`，没有交互输入或窗口依赖。

追踪追加到 `logs/cpu/trace.log`，自动创建目录并保留旧日志。每行有时间戳、宿主源码文件名和行号，以及客体 PC、原始四字节、助记符、执行后的八个寄存器和状态。状态编号为运行 0、停止 1、故障 2、预算耗尽 3；最后一次回调发生在预算耗尽标记之前，所以其状态仍是运行。日志前缀的 `demo.c:行号` 是宿主输出位置，PC 才是客体指令地址。日志创建或输出失败会使程序返回失败。

## 2. 文件分工

| 文件 | 学习重点 |
| --- | --- |
| `src/cpu/cpu.h` | CPU 状态、事件、错误码和接口契约 |
| `src/cpu/cpu.c` | 取指、解码、原子校验、执行与有界运行 |
| `src/cpu/programs.h` | 直接可读的机器码及循环地址 |
| `src/cpu/demo.c` | 宿主输出、观察回调与日志 |
| `tests/cpu_test.c` | 指令语义、边界条件与故障不变量 |

CPU 核心仅使用 ISO C，不打印、不访问文件；追踪复用项目日志记录器，其目录创建使用 POSIX API。每个 `Cpu` 内含约 64 KiB 内存，由调用方拥有，无动态分配。

## 3. 机器状态与编码

- `r0`～`r7`：八个可写的 16 位无符号寄存器，初始为零，`r0` 也可以修改。
- 内存：65536 个八位字节，代码与数据共用。没有页表、保护模式或代码段权限。
- PC：用 32 位无符号整数保存字节地址，避免末尾顺序执行时回绕到零。
- 指令：固定四字节 `[opcode, a, b, c]`；立即数或地址为 `b | (c << 8)`，范围 0～65535。
- 指令地址必须四字节对齐；16 位数据允许非对齐读写，采用逐字节小端访问，不转换成宿主 `uint16_t *`。

| 操作码 | 助记符 | 字段与执行语义 |
| --- | --- | --- |
| 1 | MOVI | `r[a] = imm16` |
| 2 | MOV | `r[a] = r[b]`，`c=0` |
| 3 | ADD | `r[a] += r[b]`，`c=0`，按模 65536 回绕 |
| 4 | SUB | `r[a] -= r[b]`，`c=0`，按模 65536 回绕 |
| 5 | LOAD | `r[a] = memory[addr..addr+1]`，小端 |
| 6 | STORE | 把 `r[a]` 的低、高字节写到 `addr`、`addr+1` |
| 7 | JMP | `PC = addr`，`a=0` |
| 8 | JZ | `r[a]==0` 时跳到 `addr`，否则顺序执行 |
| 9 | OUT | 产生输出事件，值为 `r[a]`，`b=c=0` |
| 10 | HALT | 停止，`a=b=c=0` |

除 JMP/HALT 外，`a` 必须小于 8；MOV/ADD/SUB 的 `b` 也必须小于 8。MOVI 的 `b/c` 是立即数，不是寄存器。未使用字段必须为零，没有标志寄存器，条件跳转直接检查寄存器值。

例如 `01 00 34 12` 表示 `MOVI r0, 0x1234`，执行后 PC 加 4。STORE 会写入 `34 12`，与宿主机器端序无关。普通指令与 HALT 成功执行后 PC 加 4，跳转则使用目标地址。最后一个合法指令地址为 65532，最后一个合法数据地址为 65534。

## 4. 案例一：累加 1～10

先设置 `r0=0`（累加器）、`r1=10`（剩余次数）、`r2=1`、`r3=1`（当前加数），共四条指令。循环从十进制地址 16 开始：

```text
16: ADD r0, r3     # 加上当前数
20: ADD r3, r2     # 当前数加一
24: SUB r1, r2     # 剩余次数减一
28: JZ  r1, 36    # 完成后转到输出
32: JMP 16        # 继续循环
36: OUT r0
40: HALT
```

第一次循环后 `r0=1, r1=9, r3=2`；第十次后 `r0=55, r1=0, r3=11`。前九轮各五条，最后一轮四条，加初始化与 OUT/HALT，总共 55 条。这是指令计数，不是模拟时钟周期；程序未模拟流水线或指令耗时。

## 5. 案例二：内存写入与读回

先让 `r0=55`，再 STORE 到 `0x0101`，清零 `r0` 后 LOAD 到 `r4`，最后 OUT/HALT。内存 `0x0101=55`、`0x0102=0`，共执行六条指令。地址故意不对齐，帮助理解逐字节访问。代码与数据共用内存，因此 STORE 也能修改后续指令；本解释器不缓存译码结果。

## 6. 失败行为与接口契约

`cpu_init` 清空全部状态。`cpu_load` 要求非空、非零且大小是四字节倍数的机器码，装载地址对齐且完整程序在内存内；成功时重置整个 CPU 并设置 PC，失败时整个 CPU 保持不变。输入数组不得与 CPU 存储重叠，所有接口中的 CPU 指针都必须有效。

`cpu_step` 先校验取指范围、对齐、操作码、寄存器、保留字段及数据/跳转地址，再更新状态。故障仅设置状态与故障原因，PC、寄存器和内存不变。JZ **即使条件不成立也校验跳转目标**，这是本教学 ISA 的规则。HALT 或故障后再次单步不会执行或输出；末尾 HALT 后 PC 可为 65536，末尾普通指令之后再次取指则报告越界。

`cpu_run` 限制最多尝试次数，防止错误程序无限循环。预算耗尽可继续调用或单步；零预算不执行指令并进入预算耗尽状态。已停止或故障状态保持不变。返回的 `executed` 只统计本次成功指令，包含 HALT、不包含故障尝试。观察回调每次尝试后接收只读借用状态，可消费 OUT 事件，不得修改 CPU 或重入执行。OUT 是教学宿主事件，不是真实硬件端口。

测试覆盖十条指令、算术上下溢出及寄存器别名、小端和非对齐读写、末尾访问、非法编码、故障原子性、循环预算、续跑以及两个案例。默认 `make test`、`make lint` 同时验证本专区。
