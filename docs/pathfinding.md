# 图形化学习寻路算法

运行 `make pathfinding` 打开窗口。程序在同一张可编辑网格上逐步展示 BFS、Dijkstra 和 A*；
算法核心位于 `src/graphics/pathfinding.h`、`pathfinding.c`，不依赖 SDL 或绘图模块。
窗口只负责输入、计时、绘制和截图。

## 操作方式

| 操作 | 效果 |
| --- | --- |
| `1` / `2` / `3` | 重新运行 BFS / Dijkstra / A* |
| `Space` | 暂停或继续 |
| `N` | 暂停时展开一个格子 |
| 鼠标左键 | 把普通/加权格切换为墙，或把墙改成普通地面 |
| 鼠标右键 | 普通地面切换为代价 9；高代价地面变回普通地面；墙变为高代价地面 |
| `R` | 恢复默认地图并重新搜索 |
| `S` | 将当前画布保存到 `exports/`，不会覆盖已有图片 |
| `Esc` | 退出 |

画布底部提供颜色图例：绿色 `START` 是起点，红色 `GOAL` 是终点，浅灰 `NORMAL` 是普通地面，
深灰 `WALL` 是墙，橙色 `COST` 是高代价地面，蓝色 `FRONTIER` 是已发现但待展开的格子，
灰蓝 `EXPANDED` 是已展开格子，紫色 `CURRENT` 是当前正在处理的格子，黄色 `PATH` 是最终路径。
窗口标题持续显示所选算法、搜索状态、展开格数、路径步数和总代价。起点和终点固定，鼠标编辑它们会被忽略。

## 三种算法比较什么

网格只允许上下左右移动。每格的代价表示“进入该格”的代价，零代表墙；起点不计入总代价。

- **BFS（广度优先搜索）**用 FIFO 队列按层展开，找到边数最少的路径。它把每一步视为等价，
  即使路径穿过昂贵地面也不会绕开；结果栏仍报告该路径的实际总代价。
- **Dijkstra**每次展开当前暂定总代价最小的格子，松弛邻居，保证找到总代价最低的路径。
- **A***使用 `f = g + h` 排序，其中 `g` 是已走代价，`h` 是曼哈顿距离乘以地图最小通行代价。
  这个启发式不会高估剩余代价，因此仍能找到最低代价路径，并通常减少探索范围；具体展开数
  取决于地图和并列节点顺序，不保证每次都少于 Dijkstra。

为了让代码适合初学者观察，Dijkstra 和 A* 使用固定数组线性扫描未展开节点，最坏时间为
`O(V²)`；BFS 使用固定容量队列，时间为 `O(V + E)`。三者都用前驱数组回溯路径，空间为
`O(V)`。每次核心 `pathfinding_step` 最多展开一个节点；窗口默认每秒推进 24 步、按 60 FPS
绘制，渲染帧率与算法步频独立。

## 阅读与验证

建议按 `PathfindingGrid`、`pathfinding_start`、`pathfinding_step`、`mark_path` 的顺序阅读，
再看 `pathfinding_demo.c` 如何把布尔状态映射成颜色。测试构造了短而昂贵的直路和长而便宜的
绕路：BFS 选择 7 步、总代价 55；Dijkstra 与 A* 选择 11 步、总代价 11。

运行 `make test-pathfinding` 检查最短步数、最低代价、无路、起终点相同和失败时保留输出；
`make sanitize-pathfinding` 使用地址与未定义行为消毒器。若安装 SDL2，
`make test-pathfinding-window` 还会在 dummy 窗口下验证算法切换、鼠标编辑、暂停单步、截图和退出。

| 验收项 | 实现与验证 |
| --- | --- |
| AC-001：图形界面可展示搜索过程 | `pathfinding_demo.c` 绘制搜索状态；窗口集成测试验证切换、编辑和逐步控制 |
| AC-002：算法与界面分离 | `pathfinding.c` 不依赖 SDL/绘图；核心测试和消毒器单独链接该模块 |
| AC-003：最多三种经典算法 | 核心仅实现 BFS、Dijkstra、A*；加权测试区分最少步数与最低总代价 |
