# 迷宫生成与寻路：观察 DFS、栈、BFS 和队列

本例先逐步生成迷宫，再逐步寻找从绿色起点到红色终点的路径。规则和绘制核心是纯 C，窗口沿用现有 SDL2 适配层；不使用递归或动态内存分配。

## 运行、操作与颜色

从仓库根目录运行，窗口需要 SDL2 和 pkg-config，与其他图形演示共用依赖：

```sh
make maze                          # 构建并打开窗口
make maze-build                    # 只构建窗口程序
make maze-debug                    # 构建 -O0 -g3 调试程序
make compile-commands-graphics     # 更新 SDL 代码提示
make test-maze                     # 无窗口核心测试，不依赖 SDL
make sanitize-maze                 # 地址和未定义行为检查，不依赖 SDL
make test-maze-window              # SDL dummy 控制、截图和主循环测试
./build/graphics/maze_demo --frames 120  # 显示指定帧数后退出
```

默认随机种子为 42，使用 DFS 回溯生成，完成后自动开始 BFS 寻路。窗口标题显示种子、阶段、搜索算法、已展开节点数量和最终路径长度；长度按移动边数计算，包含的格子数量是长度加一。

| 操作 | 效果 |
| --- | --- |
| Space | 暂停/继续 |
| N | 暂停时推进一个生成或搜索步骤 |
| R | 用当前种子重建，保留寻路算法和暂停状态 |
| G | 种子加一，生成新迷宫，保留寻路算法和暂停状态 |
| 1 | 在现有完整地图上重新运行 BFS |
| 2 | 在现有完整地图上重新运行 DFS |
| S | 保存当前画布为 `exports/` 内的 BMP，不覆盖已有图片 |
| Esc / 关闭窗口 | 释放窗口资源并退出 |

生成期间忽略 1/2，防止搜索半成品地图；重寻路保留暂停状态，暂停时需按 N 或 Space 继续。忽略自动重复键，种子以 uint32_t 保存，达到最大值后递增会回绕为零。没有鼠标编辑、地图导入或玩家移动操作。

| 颜色 | 含义 |
| --- | --- |
| 深灰 | 墙 |
| 浅灰 | 已生成但尚未发现的通道 |
| 蓝色 | 已发现、等待展开的搜索节点 |
| 灰蓝 | 已展开节点 |
| 橙色 | 当前生成房间或当前展开节点 |
| 黄色 | 找到的完整路径 |
| 绿色 / 红色 | 起点 / 终点，优先于其他颜色 |

网格为 39×29，每格占 8×8 逻辑像素，画布四周留 4 像素边距；实际填充 7×7，留细缝便于识别格子。逻辑画布仍是 320×240，窗口为 640×480。起点 `(1,1)`，终点 `(37,27)`，外边界始终是墙。

## 1. 从二维坐标到一维数组

所有格子用 `id = y * MAZE_WIDTH + x` 编号。反向转换为 `x = id % MAZE_WIDTH`、`y = id / MAZE_WIDTH`。MazeWorld 内包含固定数组，容量足够容纳每个格子，无外部资源所有权。

maze_is_open 先检查坐标，再读取数组，地图外视为墙。不直接用 id 加减一判断左右邻居，否则可能把某行最右格连接到下一行最左格。

## 2. DFS 回溯如何生成迷宫

奇数坐标是房间，相邻房间相隔两格，中间一格是墙；初始地图全部封闭，只打开起点。

每个生成步骤：

1. 查看栈顶房间，收集四个方向中尚未打开的相邻房间。
2. 若有候选，随机选一个，打通中间墙和新房间，并将新房间压栈。
3. 若没有候选，弹出当前房间，退回上一个房间继续尝试。
4. 栈空表示全部房间已访问，自动初始化寻路状态。

这是深度优先搜索：优先深入，遇到死路回溯。显式数组栈取代递归，便于观察 depth 的变化。每次只连到未访问房间，不引入环；生成出的全部房间连通，称为“完美迷宫”，两点之间路径唯一。

本尺寸有 19×14=266 个房间。挖通 265 次，弹栈 266 次，共 531 个生成步骤；最终共有 531 个通道格。随机流采用独立 uint32_t 线性同余状态，不影响其他示例。高位取模选择候选可能有轻微分布偏差，也不保证每种迷宫等概率；它用于可重复教学，不用于安全随机。

## 3. BFS 与 DFS 为什么不同

寻路把每个通道格视为节点，四方向相邻通道视为边，每次移动代价相同。

**BFS 使用 FIFO 队列**：从 head 取出一个节点，将新邻居追加到 tail。先展开距离近的层，再展开距离远的层；无权图中第一次发现节点时记录的前驱给出最短路径。

**DFS 使用 LIFO 栈**：从 tail 弹出一个节点，将新邻居压栈，优先探索最新加入的分支。它可以找到路径，但在有环图中不保证路径最短。

两种算法都在入队/入栈时标记 discovered，避免同一格重复加入。BFS 每格最多入队一次，因此数组队列即使不循环复用，也不会超过 MAZE_CELLS 容量。DFS 的待处理节点也不会重复，容量同样足够。

固定邻居顺序为上、右、下、左；DFS 后进先出，通常优先展开最后加入的方向。搜索过程与展开数量可能不同，但本例生成地图路径唯一，因此 BFS 和 DFS 找到的最终路径相同。测试另外构造有环地图，让 BFS 找到 62 步短路、DFS 沿当前顺序找到 106 步绕路，展示最短路保证的区别。

## 4. 前驱链如何变成黄色路径

首次发现 next 时记录 `parent[next] = current`，起点前驱为 -1。终点出队/出栈后，从终点沿 parent 回溯至起点，将所有格子的 path 标志设为 true，并统计边数。

前驱只写一次，每个新节点来自已经发现的节点，不会形成前驱环。若前沿为空还未遇到终点，进入 no-path 状态；起点或终点被封闭时也明确报告无路。生成地图始终可达，无路分支供测试和以后扩展使用。

生成阶段、寻路阶段、找到路径、无路是四个独立状态。结束后 step 不再改变世界；重新寻路清空发现、展开、前驱和路径状态，但不改变地图。

## 5. 时间、性能与调试

默认目标绘制帧率为 **60 FPS**，算法以固定步长 **每秒 120 步**推进，一帧可能执行多个步骤。生成约需 4.43 秒，实际显示耗时受系统调度影响。一次生成步骤是挖通或回退，一次搜索步骤是展开一个节点，不是让整条路径一次完成。

单帧最多累计 0.1 秒，避免长断点后大量补算；暂停不积累时间，切换暂停、重建和重寻路丢弃当前帧增量。SDL_Delay 用于主动限速，不保证精确 FPS，也不保证长停顿后模拟追随真实时间。

生成、寻路总体时间为 O(V+E)，存储为 O(V)，这里每格最多四邻居。绘制每帧扫描整张固定网格。代码侧重可观察算法，不加入性能竞赛或复杂图形系统。

VS Code 选择 `C: 迷宫生成与寻路` 按 F5。建议按 `maze.h → maze.c → maze_demo.c` 阅读，在栈压入/弹出、队首读取、前驱写入和路径回溯处设断点。源码包含参数、边界和关键算法的中文注释。

默认 make test 和 make lint 包含纯 C 核心，不打开窗口或要求 SDL。核心测试覆盖多个种子、连通无环、房间覆盖、路径相邻性、可重复性、BFS 最短路、DFS、无路和绘制。SDL dummy 测试验证暂停单步、重建、算法切换、时间、自动退出和截图失败后继续运行。
