# 落沙模拟：沙、水与墙

这个示例把画布划分为网格，用简单局部规则实现沙粒堆积、水向低处流动、沙沉入水中。它是教学用的元胞模拟，不包含真实流体压力、黏度或连续刚体碰撞。计算核心为纯 C，SDL2 只负责窗口、输入和呈现。

## 运行与操作

沿用 [二维引擎](graphics_2d.md) 的 SDL2 与 pkg-config 环境，在仓库根目录运行：

```sh
make sand                    # 构建并启动
make sand-build              # 仅构建
make sand-debug              # -O0 -g3 调试版本
make compile-commands-graphics
./build/graphics/sand_demo --frames 120  # 显示 120 帧后退出
```

| 操作 | 效果 |
| --- | --- |
| 1 / 2 / 3 | 选择沙 / 水 / 墙 |
| 左键点击、拖动或按住 | 添加选定物质，仅填充空气格 |
| 右键点击、拖动或按住 | 擦除内部物质，优先于左键 |
| [ / ] | 减小 / 增大笔刷，半径 1..8 格，默认 3 |
| Space | 暂停 / 继续 |
| N | 暂停时演化一步，运行时忽略 |
| R | 恢复示例沙块、水块和平台，步数归零 |
| C | 清空内部，保留外圈边界墙，步数归零 |
| S | 保存当前画布 BMP 到 `exports/sand-<时间>-<序号>.bmp` |
| Esc / 关闭窗口 | 退出并释放资源 |

R/C 保留暂停状态、材料和笔刷大小，并停止持续绘制。暂停时仍能点击和拖动编辑；按住鼠标静止时不会持续演化或补充，按 N 只演化一次。运行时每个模拟步先补充笔刷物质，再更新网格，可以连续倒沙。黄色为沙、蓝色为水、灰色为墙、深色为空气；窗口标题显示材料、笔刷半径、步数与暂停状态。

图片独占创建，不覆盖用户图片；截图失败在终端报错后继续。保存的是本帧事件、模拟和绘制之后的 320×240 逻辑画布，不含系统鼠标指针。

## 网格与物质规则

网格为 **160×120**，每格覆盖 2×2 个逻辑像素，默认窗口 640×480。原点在左上角，x 向右、y 向下。最外圈是不可修改的墙，形成封闭容器；中心在外圈的笔刷请求忽略，靠边圆形笔刷裁切到内部。

每格用 `uint8_t` 保存一个物质编号：空气、沙、水或墙，没有单独粒子对象。

1. **沙**：先尝试正下方，再尝试两个斜下方；可进入空气，也可与水交换位置。三个位置都受阻则静止。
2. **水**：先尝试向下、斜下移动，再尝试左右水平移动，优先沿同一行空气通道向最近的可下落位置靠近；找不到或等距时使用本步左右优先方向。每次仍只移动一格，只进入空气，不能主动穿过沙或墙。
3. **墙**：不会自行移动，内部墙可以擦除。
4. **空气**：代表空位置，不参与更新。

沙水交换用局部规则表示“沙比水重”，不计算真实密度。斜落只检查目标格，不做连续几何的拐角碰撞检测；一格孔隙和平台会体现离散网格的特点。添加物质不覆盖已有沙、水或墙，需要先擦除再替换。

## 为什么更新顺序重要

本示例采用**原地交换 + 移动标记**，与生命游戏读取旧代、写入新代的同步规则不同。

- **自底向上**：先处理下面的粒子，上方粒子可填入它空出来的位置；落下后不会在同一遍历中再次向下运动。
- **左右交替**：每步切换列遍历方向和斜落/水平优先方向，减小始终向左或向右的偏置；水的水平移动还查找可达下落位置，避免相邻两步左右摆动而无法流向平台边缘。不保证每帧严格镜像对称。
- **moved 标记**：每步清空标记，移动目标标记为已移动，避免水向扫描前方流动后再次移动。
- **沙水交换**：源格现在变成被抬起的水，也必须标记，防止该水在同一步再次运动。
- **源格变空气**：不标记空出来的格子，让上方物质正常填入；标记空气会人为阻塞连续下落。

每个粒子每步最多移动一次。移动通过交换格子完成，不创建或销毁物质，所以没有鼠标编辑时，沙、水和墙的格数分别守恒。确定的初始状态与输入序列产生确定结果，没有随机数。`steps` 到 `UINT64_MAX` 后饱和，独立的方向位仍继续交替。

## 鼠标与连续笔刷

鼠标坐标按窗口实际尺寸映射到网格，乘法先转为 `int64_t`，避免整数溢出。快速拖动时，用 Bresenham 算法连接前后笔刷中心，再在路径上的每格盖圆形笔刷，避免事件间距大时产生断线。

鼠标松开、移动事件不再包含对应按钮、窗口失焦或离开窗口都会停止持续绘制；重新进入窗口后需要再次按下。无效窗口尺寸和窗口外坐标忽略并取消笔刷。仅有鼠标移动不会自动开始绘制。

## 帧率与接口契约

目标显示 **60 FPS**，模拟固定 **1/60 秒**一步。真实耗时累积到 accumulator，不足一步的余量留到下一帧。单帧最多接收 0.1 秒、追赶六步，长停顿的额外时间丢弃；暂停不积累时间，Space/R/C 清除余量。实际帧率受绘制、截图和系统调度影响。

`SandWorld` 持有网格、标记和计数，无动态内存分配，约 40 KiB；窗口使用静态对象。先调用 `sand_reset`，之后只通过接口修改，可只读观察 `cells`。接口不负责修复外部写坏的状态。

`sand_paint` 接受内圈中心、半径 0..8 与合法物质；非法参数不改变状态。半径零用于核心测试和单格构建场景，窗口笔刷最小为一。返回 true 表示请求有效，不代表一定新增了格子。更新和绘图拒绝空指针；非法绘图地址不修改画布。

## 文件与验证

| 文件 | 职责 |
| --- | --- |
| `src/graphics/sand.h/c` | 网格、笔刷、移动规则和软件绘图，无 SDL 依赖 |
| `src/graphics/sand_demo.c` | 连续输入、场景、暂停、计时和截图 |
| `tests/sand_test.c` | 单步下落、斜落、水流、交换、守恒与边界 |
| `tests/sand_window_test.c` | 笔刷路径、映射、按键、时间与截图主循环 |

```sh
make test-sand
make sanitize-sand       # 地址与未定义行为消毒器
make test-sand-window    # SDL dummy 驱动，无实际窗口
make test
make lint
```

窗口截图测试使用临时目录，保留用户已有图片。VS Code 选择 `C: 落沙模拟` 按 F5，或运行任务 `C: 测试落沙核心`。建议暂停并在 `try_move` 设置条件断点，观察格子交换与标记，再按 N 单步。

可以继续练习：增加油并定义密度顺序；用颜色轻微变化表现沙粒；增加火焰、烟和材料转化；用活动区域减少扫描范围。当前实现只含沙、水、墙，不含化学反应、压力求解或场景文件保存。
