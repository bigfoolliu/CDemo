# 随机森林：自助采样、随机特征与袋外评估

本案例对应[学习计划阶段 9.3](50_deep_learning_plan.md)。[`src/ml/17_random_forest.c`](../src/ml/17_random_forest.c) 用固定容量数组实现一个二维二分类随机森林，并与单棵 CART 风格决策树比较。每棵森林树会对训练集有放回抽样，再在每个非纯节点随机挑一个特征寻找基尼切分；预测时由所有树投票。

```sh
make random-forest
make sanitize-random-forest
```

`make random-forest` 会运行三个固定种子的实验，不写文件。当前 Makefile 没有 `test-random-forest` 专项断言目标；消毒器目标运行同一个演示程序，检查这些执行路径上的内存和未定义行为。

## 任务数据从哪里来

训练集和测试集都是 $8\times8$ 网格。令行索引 $r$、列索引 $c$ 分别从 $0$ 到 $7$，偏移量为 $\delta$；网格点坐标由 `make_samples` 计算：

$$
x_{r,c}=-0.875+0.25c+\delta,\qquad y_{r,c}=-0.875+0.25r+\delta
$$

其中训练集使用 $\delta=0$，测试集使用 $\delta=0.0625$。圆内标签为正类，边界也归负类：

$$
z_{r,c}=
\begin{cases}
1,&x_{r,c}^{2}+y_{r,c}^{2}<0.55\\
0,&x_{r,c}^{2}+y_{r,c}^{2}\ge0.55
\end{cases}
$$

例如训练网格的 $(r,c)=(0,0)$ 得到 $(x,y)=(-0.875,-0.875)$，平方距离为 $0.875^2+0.875^2=1.53125$，因此标签为 $0$；$(r,c)=(3,3)$ 得到 $(-0.125,-0.125)$，平方距离为 $0.03125<0.55$，因此标签为 $1$。

代码把一维样本下标设为 $i=8r+c$。训练时若 $(29i+7)\bmod13=0$，就翻转标签；在 $i\in\{0,\ldots,63\}$ 中，被翻转的下标是 $2,15,28,41,54$，共 $5$ 条。测试集不加噪声。当前生成结果是训练正类 $33$ 个、负类 $31$ 个；干净测试集正类 $28$ 个、负类 $36$ 个。

多数类基线只根据训练集选择类别。训练集中正类较多，所以它总预测 $1$：训练错 $31/64$，在干净测试集上错 $36/64$。这说明基线只利用了类别占比，没有学到圆形边界。

## 随机数状态与一次自助采样

`random_next` 使用 `uint32_t` 状态。每次更新先按 $2^{32}$ 取模，再返回新状态的高 $16$ 位：

$$
s_{\ell+1}=(1664525s_\ell+1013904223)\bmod2^{32},\qquad
u_\ell=\left\lfloor\frac{s_{\ell+1}}{2^{16}}\right\rfloor
$$

这里 $s_\ell$ 是第 $\ell$ 步的 $32$ 位状态，$u_\ell$ 是返回的 $16$ 位伪随机整数。令 $b$ 表示代码参数 `upper_bound`，`random_index` 返回的下标可写为 $u_\ell\bmod b$。本例的范围只用 $64$ 个样本或 $2$ 个特征；它们都整除 $2^{16}$，所以对均匀的 $16$ 位输入，取模映射本身不会造成余数不均。不过线性同余发生器是确定性教学工具，不是独立随机源，也不适用于安全场景。

单独演示一次状态更新：若 $s_0=2025$，则 $s_1=(1664525\cdot2025+1013904223)\bmod2^{32}=89600052$，返回值为 $u_0=\lfloor89600052/65536\rfloor=1367$。若此时 `upper_bound` 为 $64$，`random_index` 得到 $1367\bmod64=23$。这只是展示 `random_next` 和取模映射的算术过程；森林成员的 bootstrap 序列还取决于前面的子种子派生步骤。

设一棵树抽取 $n$ 次，原训练集也有 $n$ 个样本；$N_{\text{OOB}}$ 表示这棵树留下的袋外样本数。每次抽取都从全部 $n$ 个样本中有放回选择一个。理想化地假设每次选择独立且均匀，一个指定样本一次也没被抽中的概率，以及一棵树期望留下的袋外样本数为：

$$
P_{\mathrm{OOB}}=\left(1-\frac{1}{n}\right)^n
$$

$$
\mathbb{E}[N_{\text{OOB}}]=n\left(1-\frac{1}{n}\right)^n
$$

本例 $n=64$，所以单个样本理论上约有 $0.365$ 的机会成为某棵树的袋外样本；每棵树期望有 $64(63/64)^{64}\approx23.36$ 个袋外样本。期望不是每棵树必须达到的数量：当前 Apple Clang $17$、主种子 $2025$ 的首棵树实际抽到 $42$ 个不同样本，留下 $22$ 个袋外样本。

在这次构建中，首棵树 bootstrap 序列的前 $12$ 个原样本下标是 `13, 57, 31, 21, 20, 50, 63, 18, 31, 7, 62, 42`。下标 $31$ 重复出现，表示同一训练样本在该树的数据中被计权两次；`in_bag[31]` 仍只是 `true`，用于标记是否曾出现，不记录重复次数。

这一步在 [`member_train`](../src/ml/17_random_forest.c#L335) 中直接写成：

```c
size_t selected = random_index(&seed, SAMPLE_COUNT);
bootstrap[i] = training[selected];
indices[i] = i;
next.in_bag[selected] = true;
```

`bootstrap` 保存每次抽中的样本，因此保留重复项；`in_bag` 只用于之后判断某个原始样本是否对本树保持袋外。

## 每个节点怎样随机切分

本模型有 $F=2$ 个特征。对每个样本数大于零、类别混合且尚未达到深度限制的节点 $t$，`build_tree_node` 先抽取一个特征编号：

$$
f_t=u^{(t)}\bmod F,\qquad F=2
$$

其中 $f_t$ 是节点 $t$ 选择的特征编号，$u^{(t)}$ 是该节点消耗的下一个随机值，$F$ 是特征总数。每个节点只随机考虑一个特征，即每个节点候选特征数 $m_{\mathrm{try}}=1$；之后在这个特征上枚举所有相邻不同值的中点，并选其中基尼增益最大的阈值。随机性来自 bootstrap 样本和节点特征选择；阈值本身不是随机挑的。

对应的 C 代码是 [`build_tree_node`](../src/ml/17_random_forest.c#L186) 中的两步：

```c
int feature = (int)(random_next(random_state) % FEATURE_COUNT);
if (!find_candidate(samples, indices, count, positives, feature, &candidate)) {
    *output = node_index;
    return true;
}
```

第一行按随机数选一个特征；第二行只在该特征上找阈值。如果该维没有正增益候选，代码就把节点留作叶子，不会继续尝试另一个特征。

对节点 $t$，令 $m_t$ 为正类数，$n_t$ 为样本数，$p_t=m_t/n_t$ 为正类比例。二分类基尼不纯度为：

$$
G(t)=2p_t(1-p_t)
$$

切分后左、右样本数为 $n_L,n_R$，且 $n_t=n_L+n_R$；子节点的加权不纯度及切分增益为：

$$
G_{\text{after}}=\frac{n_L}{n_t}G(L)+\frac{n_R}{n_t}G(R)
$$

$$
\operatorname{Gain}=G(t)-G_{\text{after}}
$$

源码中的 `impurity(positives, count)` 对应 $G(t)$，`find_candidate` 的 `child_impurity` 对应 $G_{\text{after}}$。它对当前特征按值排序，随扫描更新左侧正类数；右侧正类数由父节点正类数减去左侧正类数得到。相同相邻特征值不生成切分点，中点阈值用 `<=` 规则划分；若最佳增益不大于 $10^{-12}$，函数返回失败，建树把当前节点保留为叶节点。

不纯度函数的实现与 $G(t)=2p_t(1-p_t)$ 一一对应：

```c
double probability = (double)positives / (double)count;
return 2.0 * probability * (1.0 - probability);
```

而 [`find_candidate`](../src/ml/17_random_forest.c#L130) 对左右子节点按样本数加权，再用父节点不纯度相减：

```c
double child_impurity =
    ((double)left_count * impurity(left_positives, left_count) +
     (double)right_count * impurity(right_positives, right_count)) /
    (double)count;
double gain = parent - child_impurity;
```

设排序后的相邻不同特征值为 $v_k$ 和 $v_{k+1}$，其中 $k$ 是当前节点排序数组的零起始位置，候选阈值取两者中点：

$$
\tau_k=v_k+\frac{v_{k+1}-v_k}{2},\qquad v_k<v_{k+1}
$$

首棵树根节点的特征 $x_1$ 在该处相邻值是 $0.625$ 和 $0.875$，代入得到 $0.625+(0.875-0.625)/2=0.75$。候选阈值还要通过基尼增益比较，只有选中的阈值才用于构造左右子节点。

### 首棵树根节点的实算

当前工具链对主种子 $2025$ 的首棵树，在根节点选中了特征 $x_1$，阈值为 $0.75$。该 bootstrap 样本共 $64$ 项、其中正类 $32$ 项。切分后左侧有 $56$ 项、正类 $32$ 项；右侧有 $8$ 项、正类 $0$ 项。下面把这些实际计数代入基尼公式：

$$
G(\text{root})=2\cdot\frac{32}{64}\cdot\left(1-\frac{32}{64}\right)=0.5
$$

$$
G(L)=2\cdot\frac{32}{56}\cdot\left(1-\frac{32}{56}\right)=\frac{24}{49}\approx0.489796,\qquad G(R)=0
$$

$$
G_{\text{after}}=\frac{56}{64}\cdot\frac{24}{49}+\frac{8}{64}\cdot0=\frac{3}{7}\approx0.428571
$$

$$
\operatorname{Gain}=0.5-\frac{3}{7}=\frac{1}{14}\approx0.071429
$$

这项计算对应 [`find_candidate`](../src/ml/17_random_forest.c#L130) 对随机选中特征枚举阈值，并由 [`build_tree_node`](../src/ml/17_random_forest.c#L186) 接受候选、分配左右样本的过程。上述根节点细节依赖当前工具链对成员子种子表达式的求值顺序；下文解释其可移植性限制。

每个树节点最大深度为 $6$，根节点深度为 $0$；纯节点或达到深度上限时立即停止。这里没有 `min_leaf` 配置，只要求切分后左右都非空。叶节点按多数类预测，正负票数相同时选 $0$。随机特征选中后若该特征找不到正增益切分，当前代码直接停止该节点，不会再尝试另一个特征；这会让树的行为依赖这次随机选择。

## 森林投票：类别与“概率”不是一回事

令 $T=31$ 为树的数量，$v_0$ 和 $v_1$ 分别是预测类别 $0$、$1$ 的树数。森林预测类别以及输出的正类投票比例是：

$$
\hat z=\begin{cases}1,&v_1>v_0\\0,&v_1\le v_0\end{cases},\qquad
q=\frac{v_1}{T}
$$

这里 $q$ 是正类树票占比，不是校准后的后验概率。`forest_predict` 只有在所有树都成功预测后，才写入类别和比例；平票归类别 $0$。

源码将投票规则与输出比例放在一起：

```c
int predicted = votes[1] > votes[0] ? 1 : 0;
double positive_fraction = (double)votes[1] / (double)forest->tree_count;
```

因此类别判断使用两类票数比较，$q$ 的分母则是森林总树数 $T$；两者用途不同。

例如主种子 $2025$ 的森林对测试点 $(-0.3125,-0.8125)$ 投出 $15$ 张正类票和 $16$ 张负类票。该点到原点的平方距离为 $(-0.3125)^2+(-0.8125)^2=0.7578125$，大于圆内阈值 $0.55$，所以真实标签为 $0$；森林也预测 $0$。接口返回的正类投票比例是 $q=15/31\approx0.4839$。它表达树之间的票数倾向，不应直接说成“该点属于正类的概率是 $48.39\%$”。

## OOB 如何形成内部评估

训练一棵树后，`member_train` 保留 `in_bag[j]`。`forest_train` 对每个原始训练样本 $j$ 检查该标记：如果为 `true`，本树不参与该样本的 OOB 预测；否则用该树预测并增加 `votes[j][label]`。设 $v_{j,0}$、$v_{j,1}$ 是样本 $j$ 的 OOB 类别票数，$V_j=v_{j,0}+v_{j,1}$ 是该样本收到的 OOB 总票数，则只在 $V_j>0$ 时计算其 OOB 预测：

```c
if (next.members[i].in_bag[sample]) {
    continue;
}
/* 用本树预测该样本后，按预测类别累计一票。 */
++votes[sample][label];
```

这段来自 [`forest_train`](../src/ml/17_random_forest.c#L448)。它实现了公式中的“只汇总没被该树抽到的样本”；树内 bootstrap 重复几次不会改变 OOB 条件。

$$
\hat z_j^{\text{OOB}}=\begin{cases}1,&v_{j,1}>v_{j,0}\\0,&v_{j,1}\le v_{j,0}\end{cases}
$$

$$
E_{\text{OOB}}=\sum_{j:V_j>0}\mathbf{1}\left[\hat z_j^{\text{OOB}}\ne z_j\right],\qquad
C_{\text{OOB}}=\sum_{j=0}^{63}\mathbf{1}[V_j>0]
$$

其中 $z_j$ 是训练标签，$\mathbf{1}[\cdot]$ 在括号条件成立时为 $1$，否则为 $0$；$E_{\text{OOB}}$ 是错误数，$C_{\text{OOB}}$ 是有覆盖样本数。没有任何袋外票的样本会被跳过；如果整批样本都没有覆盖，`oob_evaluate` 返回失败。

当前工具链、主种子 $2025$ 下，训练样本 $0$ 的坐标是 $(-0.875,-0.875)$，真实标签是 $0$。它在该森林中获得 $13$ 张 OOB 类别 $0$ 票、$1$ 张 OOB 类别 $1$ 票，共由 $14$ 棵树覆盖，因而预测类别 $0$。此例展示 OOB 不是“每棵树都对训练样本投票”：只有没见过该样本的树才计入。

OOB 让每个训练点都可以由未把它放进 bootstrap 数据的树来评估，但不同样本的 OOB 树集合不同，且它们仍参与森林中其他树的训练。因此程序还保留偏移网格测试集，并明确报告测试结果；固定的合成实验不等于真实数据泛化保证。

## 主程序结果如何读

`baseline_tree_train` 用全部训练点、每个节点的全部特征和确定性最大基尼增益建立单棵深度 $6$ 的基线树。每个森林则由 $31$ 棵深度 $6$ 的成员树组成。主程序使用种子 $2025$、$2026$、$2027$ 分别重复森林实验；三个种子对应不同的 bootstrap 和特征选择序列，单棵 CART 基线保持不变。

运行 `make random-forest` 的当前结果为：

```text
训练集多数类基线错误：训练 31/64，测试 36/64
种子 | 单树训练/测试错误 | 森林训练/测试错误 | 袋外错误/覆盖样本
2025 | 3/64, 10/64 | 5/64, 8/64 | 9/64
2026 | 3/64, 10/64 | 4/64, 7/64 | 8/64
2027 | 3/64, 10/64 | 3/64, 8/64 | 7/64
森林测试准确率均值：88.0%；袋外准确率均值：87.5%
```

准确率对每次运行按 $1-E/N$ 计算，其中 $E$ 是错误数，$N$ 是该组评估样本数；最终均值再对三个种子求算术平均。森林测试正确数依次为 $56$、$57$、$56$，所以平均准确率是 $((56+57+56)/(3\cdot64))\times100\%\approx88.0\%$。OOB 错误数是 $9$、$8$、$7$，覆盖数均为 $64$，所以平均 OOB 准确率是 $((55+56+57)/(3\cdot64))\times100\%=87.5\%$。在这个含噪声的圆形任务上，三次森林的测试错误都低于单树的 $10/64$，但三次实验样本太少，不能推出森林总会优于单树。

## 固定种子的可移植性注意

`forest_train` 为每棵树派生子种子的语句是：

```c
uint32_t member_seed = random_next(&seed) ^ seed ^ (uint32_t)(i * UINT32_C(2654435761));
```

`random_next(&seed)` 会修改 `seed`，同一表达式中的另一个操作数也读取 `seed`。C23 草案说明，普通二元运算的操作数通常不按固定先后顺序求值；函数体执行与调用者中的其他求值则是不确定先后、但每次执行中会有先后关系。因此这里不应直接称为未定义行为，但实现可能在调用前或调用后读取 `seed`，从而派生出不同子种子和森林。可将函数调用与 XOR 拆成两个完整语句，并明确要混合调用前还是调用后的状态。参见 [WG14 C23 草案 N3096 第 6.5 与 6.5.2.2 节](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3096.pdf)。

当前 Apple Clang $17$ 的构建、普通运行和消毒器运行给出一致输出；这只能确认当前工具链的行为。即使消除该求值顺序歧义，线性同余伪随机数也不等于统计独立的随机流。若要做可复现的跨编译器实验，应先固定子种子派生步骤，再固定随机数算法和整数宽度，并用回归断言锁住关键样本序列。

## 边界与继续练习

- `member_train` 每棵树恰好抽取 $64$ 次；抽样可重复，树的有效唯一训练样本数可能少于 $64$。`in_bag` 只记是否出现，重复次数由 `bootstrap` 数组保留。
- `build_tree_node` 和基线树使用最多 $127$ 个定长节点；最大样本数是 $64$，最大切分深度是 $64$，主程序选择 $6$。纯节点、达到深度上限或抽中无有效增益的特征时停止。
- `forest_train` 先在局部 `next` 和局部票数数组中完成整个森林，全部成功后才替换 `forest` 并复制 OOB 票数。树和样本使用定长数组，没有模型文件或日志副作用。
- 训练入口依赖本例的 `make_samples` 生成合法的二分类数据；`forest_train` 不逐条验证训练坐标和标签。复用这些静态函数处理外部数据时，应补上有限坐标范围和标签校验。预测阶段的 `tree_predict` 会检查两个输入坐标均有限且位于 $[-1,1]$。
- `random_index` 要求 `upper_bound>0`，当前调用只传非零常量。随机数发生器不用于密码学、安全抽签或需要统计保证的生产系统。

建议依次阅读 [`member_train`](../src/ml/17_random_forest.c#L335)、[`build_tree_node`](../src/ml/17_random_forest.c#L186)、[`forest_train`](../src/ml/17_random_forest.c#L448)、[`forest_predict`](../src/ml/17_random_forest.c#L394) 和 [`oob_evaluate`](../src/ml/17_random_forest.c#L541)。`make random-forest` 验证固定实验可以完整训练并打印指标；`make sanitize-random-forest` 对同一流程运行地址与未定义行为消毒器。仓库没有针对随机森林的独立断言测试，所以这些结果不覆盖任意输入、不验证统计性质，也不证明真实数据上的效果。构建定义见 [`Makefile`](../Makefile#L1128)。
