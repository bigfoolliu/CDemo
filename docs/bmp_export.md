# BMP 图片导出：从像素数组到二进制文件

本例将二维引擎的画布保存为 24 位、未压缩 BMP。编码与文件写入使用 C 标准库，不调用 SDL_SaveBMP，也不依赖图片库；errno 错误码采用 POSIX 平台约定，目录创建单独使用 POSIX API。重点学习文件头、小端字节序、颜色通道和行填充。

## 使用方式

在仓库根目录运行：

```sh
make bmp                      # 无需 SDL，绘制示例并导出一张图片
make bmp-build                # 只构建导出程序
make bmp-debug                # 构建 -O0 -g3 调试版本
make test-bmp                 # 临时目录中的格式和文件行为测试
make sanitize-bmp             # 地址与未定义行为检查
```

程序输出实际保存路径，例如 `exports/demo-20261010-173000-0000.bmp`。目录自动创建；文件名包含本地时间和序号，同名时尝试下一个序号，不覆盖旧图片。生成图片已加入 Git 忽略规则，`make clean` 保留图片。

在二维图形、粒子喷泉和生命游戏窗口中按 **S** 保存当前绘制帧，终端显示路径。可以先用 Space 暂停，再单步并截图，方便对比演化。运行时也能截图；保存的是处理本帧事件和更新之后绘制的画布，不是屏幕上一帧。忽略重复键，同一显示帧中的多个截图请求合并为一次。

图片为原始 **320×240** 逻辑像素，不包含标题栏或窗口的两倍放大。颜色取画布的 RGB 通道，忽略 alpha。本例不实现读取 BMP、透明度、压缩、灰度或模糊。

VS Code 选择 `C: BMP 图片导出` 按 F5，无需安装 SDL。可在文件头写入和像素循环处设断点，观察每个字节；任务 `C: 测试 BMP 导出` 执行格式测试。

## 1. 文件布局

这里使用 14 字节文件头加 40 字节 BITMAPINFOHEADER，不含调色板。像素从偏移 54 开始。布局依据 Microsoft 的 [Bitmap Storage](https://learn.microsoft.com/en-us/windows/win32/gdi/bitmap-storage) 文档。

| 文件偏移 | 字节数 | 本例内容 |
| --- | --- | --- |
| 0 | 2 | 签名 `BM` |
| 2 | 4 | 整个文件长度 |
| 6 | 4 | 保留字段，零 |
| 10 | 4 | 像素偏移，54 |
| 14 | 4 | 信息头长度，40 |
| 18 / 22 | 各 4 | 宽度 / 正高度 |
| 26 | 2 | 色彩平面，1 |
| 28 | 2 | 位深，24 |
| 30 | 4 | 压缩方式，0，即 BI_RGB |
| 34 | 4 | 像素数据长度，包含行填充 |
| 38～53 | 16 | 分辨率与调色板计数，零 |

多字节整数按**小端**编码：低位字节先写。例如 54 编码为 `36 00 00 00`。`little_endian` 通过移位逐字节填入数组；不能直接把 C 结构体写入文件，因为结构体可能包含填充，主机字节序也未必与文件相同。

## 2. RGB 数值与 BGR 文件字节

画布颜色数值为 `0xFFRRGGBB`，24 位 BMP 每像素写三个字节：

```text
B = color 的低 8 位
G = (color >> 8) 的低 8 位
R = (color >> 16) 的低 8 位
```

因此红色 `(255,0,0)` 在文件里是 `00 00 FF`。最高字节不写入，也不参与透明混合。代码通过移位取通道，不依赖整数在当前机器上的内存排列。

## 3. 为什么从下往上写，还要补齐一行

正高度的 BMP 第一条像素行对应图像底部，所以代码从 `height - 1` 遍历到 0；每行内部仍从左到右。BMP 行需按四字节对齐，规则见 [Bitmap Header Types](https://learn.microsoft.com/en-us/windows/win32/gdi/bitmap-header-types)。

```c
stride = (width * 3 + 3) / 4 * 4;
image_size = stride * height;
file_size = 54 + image_size;
```

| 宽度 | 颜色字节 | 填充字节 | 行长度 |
| --- | --- | --- | --- |
| 1 | 3 | 1 | 4 |
| 2 | 6 | 2 | 8 |
| 3 | 9 | 3 | 12 |
| 4 | 12 | 0 | 12 |

填充使用零，不是额外像素。完整画布宽 320，行长度 960，无需填充；文件长度为 `54 + 960 × 240 = 230454` 字节。测试专门使用宽 1～4 验证所有填充情况，避免完整画布掩盖错误。

## 4. 接口、所有权与失败行为

- `gfx_bmp_write(stream, canvas, width, height)` 编码画布左上角区域；尺寸必须在画布范围内。流由调用者以二进制方式打开和关闭，函数从当前位置写入并刷新。应从位置零开始形成完整 BMP；失败可能留下部分数据。
- `gfx_bmp_save(canvas, path)` 保存完整画布，父目录须存在。通过 `fopen(path, "wbx")` 独占创建，已有文件时失败；检查写入、刷新和关闭错误，失败时尝试移除本次创建的不完整文件，清理失败时文件可能保留。
- `gfx_bmp_capture(canvas, name, path)` 创建 `exports/` 并生成唯一名称；输出数组至少为 `BMP_CAPTURE_PATH_SIZE` 字节。前缀只允许 ASCII 字母、数字、下划线和连字符。目录创建使用 POSIX `mkdir`，与纯 C 编码分离。

以上函数失败返回 false，并通过 `errno` 提供原因。窗口截图失败会打印错误并继续演示；独立导出程序失败以非零状态退出。图片不属于日志，不写入 `logs/`；本功能不新增持久日志。

`fwrite` 返回成功不代表缓冲数据已经写到底层文件，仍要检查 `fflush` 与 `fclose`。如果 `exports` 被同名普通文件占用，明确报告目录错误并保留该文件。

## 阅读与验证

按 `bmp.h → bmp.c → bmp_capture.c → bmp_demo.c` 阅读。先观察文件头各偏移，再看逆序行遍历、BGR 通道和零填充，最后学习独占创建与错误清理。

默认 `make test` 和 `make lint` 包含 BMP 核心验证，无需 SDL；测试检查文件头、长度、颜色顺序、上下方向、四种行填充、重复导出及失败路径。测试文件都在临时目录中创建，保留用户已有图片。三个 SDL dummy 窗口测试还发送 S 事件，验证实际保存以及保存失败后继续运行。

练习：用 `gfx_bmp_write` 导出 101×80 的左上角区域，观察一字节行填充；交换 R/B 通道看颜色变化；改变上下行顺序观察翻转。修改后运行格式测试和消毒器。
