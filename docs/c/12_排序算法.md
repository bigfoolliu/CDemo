# 图形化学习排序算法（sorting algorithms）

运行 `make sorting`，在柱状图上逐步比较冒泡、插入、选择和快速排序。纯 C 核心位于
`src/graphics/sorting.h`、`sorting.c`；窗口只负责键盘、计时和绘制，不参与排序决策。
按主键盘或数字小键盘的 `1` / `2` / `3` / `4` 切换算法，所有算法会从同一组确定性数据重新开始。
画布左上角会持续显示当前算法名称，快速排序使用 `QUICK` 标记。

## 1. 操作与图例

| 操作 | 效果 |
| --- | --- |
| `1` / `2` / `3` / `4` | 重新运行冒泡 / 插入 / 选择 / 快速排序 |
| `Space` | 暂停或继续 |
| `N` | 暂停时执行一个排序微步骤 |
| `R` | 生成下一组确定性数据并重置当前算法 |
| `S` | 将当前柱状图保存到 `exports/`，不会覆盖已有图片 |
| `Esc` | 退出 |

界面底部的 `DATA`（蓝色）表示普通数据，`CHECK`（橙色）表示正在比较的元素，
`PIVOT`（紫色）表示快速排序当前分区的枢轴，`WRITE`（亮绿色）表示本步发生写入的位置，
`DONE`（深绿色）表示已排定位置或有序前缀。
窗口标题显示算法、运行状态、键值比较次数和数组槽位写入次数。柱高对应元素的键值；重复键
的原始次序保存在 `SortingItem.original_order`，不影响排序比较。

## 2. 四种算法

- **冒泡排序**比较相邻元素，较大的值逐步移到未排序区末尾。每趟结束后将末尾一格标为已排定；
  若某一趟没有交换则提前完成。稳定，额外空间为 `O(1)`，最坏时间为 `O(n²)`，已有序时为 `O(n)`。
- **插入排序**将下一个元素暂存在 `key`，向左比较并右移较大元素，再把 `key` 放入空位。
  界面在空位处绘制暂存的 `key`。只在严格大于时右移，因此稳定；额外空间为 `O(1)`，
  最坏时间为 `O(n²)`，已有序时为 `O(n)`。
- **选择排序**每趟扫描未排序后缀，找出最小元素并与后缀首项交换。比较次数固定为
  `n(n-1)/2`，额外空间为 `O(1)`，交换次数最多 `n-1`；由于远距离交换，它通常不稳定。
- **快速排序**使用迭代版 Lomuto 分区，固定选择区间末元素为枢轴。扫描值小于或等于枢轴时，
  将它交换到左侧区域；分区归位后，把左右子区间压入固定容量的显式栈，避免递归调用。
  平均时间为 `O(n log n)`、最坏为 `O(n²)`，显式栈最坏占用 `O(n)`；分区交换可能改变相等键的
  次序，因此不稳定。末元素枢轴在已排序或全相等输入上会产生最坏情况。

`sorting_step` 每次最多比较一对键；快速排序把枢轴归位作为独立步骤。
为了完成一次比较，可以进行一次交换或插入移动。
`comparisons` 只计键比较，`writes` 计写入数组槽位的次数：一次交换算两次写入。
窗口以每秒 60 个排序步骤推进，并独立以 60 FPS 绘制；真实帧间隔最多累计 0.1 秒，避免卡顿后
无限追赶。单步可用于仔细检查一次比较、移动和状态变化。

## 3. 阅读与验证

建议依次阅读 `SortingItem` 和 `SortingState`，再看 `sorting_start` 如何建立状态，以及
`sorting_step` 如何逐次推进四种算法。快速排序可从 `quick_low`、`quick_high`、`quick_cursor` 和
`quick_boundary` 观察 Lomuto 分区不变量，再查看 `quick_stack_low/high` 如何保存尚未处理的区间。
插入排序的 `hole` 与 `key` 展示了“暂存一个元素、右移较大
元素、最后填入空位”的过程；选择排序则可与冒泡和插入对照，观察稳定性差异。

运行 `make test-sorting` 验证排序结果、重复键稳定性、比较/写入计数、单步和失败边界；
`make sanitize-sorting` 使用地址与未定义行为消毒器。若安装 SDL2，`make test-sorting-window`
会在 dummy 窗口下验证控件、图例、计时、截图和有界主循环。VS Code 选择 `C: 排序算法演示` 调试。

| 验收项 | 实现与验证 |
| --- | --- |
