# 曼德勃罗分形（Mandelbrot fractal）：复数迭代与像素着色

本例把复平面中的每个采样点当作常量 c，从 z₀=0 开始反复执行 zₙ₊₁=zₙ²+c，根据逃逸次数绘制颜色。规则、坐标和绘图是纯 C，SDL2 负责窗口与输入，沿用项目的 BMP 导出功能。

## 1. 运行与操作

从仓库根目录运行。窗口需 SDL2 和 pkg-config，与其他图形演示共用依赖：

```sh
make mandelbrot                       # 构建并打开窗口
make mandelbrot-build                 # 只构建
make mandelbrot-debug                 # 构建 -O0 -g3 调试版本
make compile-commands-graphics        # 更新 SDL 代码提示
make test-mandelbrot                  # 纯 C 数值与像素断言，无需 SDL
make sanitize-mandelbrot              # 地址与未定义行为检查
make test-mandelbrot-window           # SDL dummy 输入、截图与有界循环测试
./build/graphics/mandelbrot_demo --frames 120  # 显示指定帧数后退出
```

默认中心为 `(-0.5,0)`，复平面可见宽度 3.5，虚轴高度 2.625，迭代上限 128。逻辑画布为 320×240，窗口为 640×480，最近邻放大。标题显示中心坐标、可见宽度和迭代上限。

| 操作 | 效果 |
| --- | --- |
| 左键点击 | 在点击位置放大两倍 |
| 右键点击 | 在点击位置缩小两倍 |
| 滚轮 | 向上放大、向下缩小，锚点为鼠标位置；支持 SDL 翻转方向标志 |
| 方向键 | 平移中心，每次移动当前宽度或高度的四分之一 |
| + / = / 小键盘 + | 迭代上限加倍，最多 1024 |
| − / 小键盘 − | 迭代上限减半，最少 32 |
| R | 恢复默认视图和迭代上限 |
| S | 将当前逻辑画布保存到 exports，不覆盖已有 BMP |
| Esc / 关闭窗口 | 清理资源并退出 |

键盘自动重复被忽略，需要逐次按键。每个滚轮事件只缩放一级，避免高速滚动一次跳过许多层。方向键移动的是视图中心：向右使中心实部增加，画面中的固定图案会向左移动。不提供拖动平移、撤销、动画或自动增加迭代上限。

## 2. 为什么简单公式会产生复杂边界

曼德勃罗集合包含那些使上述迭代序列保持有界的 c。画布中的不同位置对应不同 c，但每次迭代的起点始终是零。

几个可以直接观察的例子：

- c=0：所有 z 都为零。
- c=-1：z 在 0 和 -1 之间交替。
- c=-2：z 从 -2 到 2，之后保持为 2。
- c=1：z 依次为 1、2、5，第三次迭代逃逸。
- c=2：第一次 z=2，第二次 z=6，第二次逃逸。

对于这个迭代，模长严格大于 2 即可判定逃逸，代码比较 `real*real + imag*imag > 4`，避免每轮求平方根。等于 4 时不能提前判定逃逸，这对 c=-2 等边界点很重要。

程序计算次数有限：达到上限仍未逃逸的点绘为黑色，但不能据此严格证明它属于集合。增加上限可能使原先的黑色点变成外部颜色，尤其是在边界附近。

## 3. 把复数平方拆为实数运算

设 z=a+bi、c=p+qi，那么：

```text
新的实部 = a*a - b*b + p
新的虚部 = 2*a*b + q
```

代码暂存新的实部，再用旧 a、b 更新虚部，最后提交实部。若先覆盖 a，再用它计算 2ab，就改变了数学公式。

这里用两个 double 展开复数计算，便于逐变量观察；并不是要求 C 必须手动实现复数，标准库的 complex.h 也提供复数类型和操作。此版本没有解析区域快速判定、周期检测、多线程或 GPU 计算。

`MandelbrotEscape` 同时记录次数和 escaped 标记：最后一次允许的迭代也可能刚好逃逸，不能仅根据“次数等于上限”把它当成未逃逸。

## 4. 像素位置如何映射到复平面

`MandelbrotView` 保存中心实部、中心虚部、可见实轴宽度和迭代上限。虚轴高度为 `span × 240 / 320`，保持两个方向单位长度相同，避免分形被拉伸。

归一化位置 u、v 均为 0..1：

```text
实部 = center_real + (u - 0.5) * span
虚部 = center_imag + (0.5 - v) * span * 240 / 320
```

画布 y 轴向下，虚轴通常向上，所以虚部使用 `0.5-v`。绘制采样每个像素的中心，纵向使用对称的半整数偏移；中心虚部为零时，上下行对应共轭位置，颜色也对称。

鼠标坐标按当前窗口宽高转换为归一化比例，不假定必须是两倍窗口，也不直接使用物理显示器像素密度。点击和滚轮事件中的位置与 SDL 窗口尺寸使用相同单位，窗口外操作忽略。

## 5. 鼠标锚点为什么不会漂移

先计算鼠标指向的旧复平面位置 anchor，再修改跨度。以实部为例：

```text
new_span = old_span * factor
new_center_real = anchor_real - (u - 0.5) * new_span
```

虚部同理。这样在相同鼠标比例位置下，新坐标仍等于 anchor，而不是每次都围绕画面中心缩放。factor=0.5 使可见范围减半，即放大两倍；factor=2 表示缩小。

本例宽度限制为 **1e-10～4**，整个可见区域限制在 **[-4,4]²**。这些边界保证普通 double 和固定迭代上限的教学范围，不支持任意精度深度缩放。非法、非有限或超限的映射/修改返回 false，保留原状态；窗口标题显示 limit reached。默认完整视图继续缩小时也可能触发宽度上限，可用 R 回到默认。

## 6. 逃逸次数怎样变成颜色

未逃逸点为黑色；逃逸点将 `iterations / max_iterations` 转为比例 t，使用 RGB 多项式调色。越早逃逸通常颜色越暗，边界附近较晚逃逸形成彩色条带。这是视觉表达，不表示距离或严格的集合成员关系。

最后一步才逃逸的点绘为亮色，避免把它与未逃逸点混淆。着色使用整数迭代次数，不实现对数平滑着色或抗锯齿；改变迭代上限也会改变外部颜色比例。

## 7. 重绘缓存、帧率与调试

显示目标为 **60 FPS**，但这是静态图像，没有每秒推进的模拟步。仅在缩放、平移、重置或调整迭代上限后重新计算；其余帧呈现缓存画布，截图使用当前计算结果。

重新计算同步执行，最多约 320×240×1024 次迭代，复杂度 O(像素数×迭代上限)。边界附近、高迭代上限时会更慢，重绘期间不承诺 60 FPS；不通过反复计算不变画布来制造动画。

默认 make test 和 make lint 包含纯 C 核心，不需要 SDL 或打开窗口。测试覆盖已知点的精确逃逸次数、严格阈值、最后一步逃逸、共轭对称、坐标比例、缩放锚点、极端输入、失败不改状态及像素可重复性；SDL dummy 测试验证鼠标、滚轮、平移、迭代限制、重置、自动退出和实际 BMP 截图。
