# C 语言基础（C language fundamentals）学习手册

本手册按初学者的学习顺序组织。先学习基础语法和对象模型，再学习 C23 的新增写法。示例是主题入口，不等同于标准的全部细节；末尾列出尚未提供独立示例的内容。

## 1. 程序如何运行

```c
#include <stdio.h>

int main(void)
{
    puts("你好，C");
    return 0;
}
```

`#include` 引入声明，`main` 是普通宿主环境的入口，花括号组成语句块，分号结束声明或表达式语句。`return 0` 表示成功退出。`//` 是行注释，`/* ... */` 是块注释，块注释不可嵌套。

构建通常经历预处理、编译、汇编和链接。每个源码经过预处理形成一个翻译单元；链接器将不同翻译单元中的定义组合起来。声明介绍名字和类型，定义提供函数实现或对象；文件作用域的暂定定义另有规则。

练习：将 `puts` 替换为 `printf`，使用 `\n` 换行，观察少写分号时的编译诊断。

## 2. 类型、变量与初始化

阅读 `src/basics/01_types.c`。

- 整数包括 `char`、`short`、`int`、`long`、`long long` 及相应无符号类型。普通 `char` 的符号性由实现决定。
- 浮点类型包括 `float`、`double`、`long double`。许多十进制小数不能精确表示，比较时要考虑误差。
- C23 的 `bool` 表示真假；`void` 可表示函数无返回值，`void *` 可表示通用对象指针。
- `const` 限制修改，不等于所有场景中的编译期常量。`volatile` 不提供线程同步，`restrict` 是指针访问约定，不能随意添加。
- 自动局部对象未初始化时不要读取；静态存储期对象默认进行零初始化。
- `sizeof` 返回 `size_t`，`sizeof(char)` 总是 1；每字节位数由 `CHAR_BIT` 给出。不要假设 `int` 永远为 32 位。
- `<stdint.h>` 提供固定宽度整数类型，但精确宽度类型是否存在取决于实现；格式化输出可使用 `<inttypes.h>` 的宏。

练习：输出不同类型的大小，给变量设置初始值，再观察整数转为浮点数后的结果。

## 3. 表达式与运算符

阅读 `src/basics/02_operators.c`。

算术运算有 `+ - * / %`，比较有 `== != < <= > >=`，逻辑有 `! && ||`，位运算有 `~ & | ^ << >>`。另有赋值和复合赋值、前后缀递增递减、条件运算符 `?:`、逗号运算符、下标、成员访问、取地址、解引用及强制转换。

整数除法向零截断；除数不能为零。有符号整数溢出是未定义行为；无符号算术按模数回绕。移位位数不能为负，也不能达到或超过提升后左操作数的位宽。位操作优先使用无符号类型。

窄整数会经历整数提升；不同类型参与运算时还有通常算术转换。混合有符号和无符号数可能改变比较结果。强制转换不能让无效地址变成有效指针。

### 3.1 前缀递增 `++i` 与后缀递增 `i++`

两种写法都会让 `i` 增加 1；区别在于表达式产生的值：

- `++i`：先增加，再产生新值。可以记成“先改，再用”。
- `i++`：先产生旧值，再完成增加。可以记成“先用，再改”。

```c
int i = 3;
int prefix_value = ++i;  /* i 变成 4，prefix_value 得到 4 */
int postfix_value = i++; /* postfix_value 得到旧值 4，随后 i 变成 5 */
```

如果递增表达式单独作为一条语句，结果没有被使用，那么 `++i;` 和 `i++;` 都只会把 `i` 增加 1。循环计数常写成 `for (int i = 0; i < count; ++i)`；对内置整数而言，选择前缀或后缀主要是风格问题，没有值得依赖的性能差异。

```c
int values[] = {10, 20, 30};
int i = 0;
int first = values[i++]; /* 先用下标 0 取出 10，再把 i 增加到 1 */
```

带副作用的表达式应保持简单。不要在同一表达式中多次修改同一个变量，例如 `i++ + i++`；C 不保证这些修改按你预想的顺序发生，这种写法会导致未定义行为。拆成多条语句更容易理解和检查。

运算符优先级决定表达式如何组合，但不保证操作数按从左到右求值；函数实参之间也没有通用的从左到右保证。逻辑运算短路；用括号明确复杂表达式的意图。

练习：预测 `7 / 2` 与 `(double)7 / 2`，比较 `&&` 与 `&` 的行为。

输出转义字符、无符号整数后缀、`puts` 和 `printf` 格式说明符见[转义字符与输出格式](09_C转义字符与格式化输出.md)，重点掌握 `%d` 对应 `int`、`%u` 对应 `unsigned int`、`%zu` 对应 `size_t`，以及 `%.1f` 控制 `double` 的显示精度。

## 4. 语句与控制流

阅读 `src/basics/03_control_flow.c`。

`if/else` 做条件分支，`switch/case/default` 做整数条件分支；`for`、`while`、`do/while` 做循环。零为假，非零为真。`break` 结束最内层循环或 switch，`continue` 进入下一轮循环，`return` 返回调用者。

`switch` 的 case 是整数常量表达式；它不会自动停止，需明确处理贯穿执行。`goto` 跳到当前函数中的标签，可用于统一清理资源；不应用它绕过对象初始化后继续读取对象。

练习：累加 1 到 100，跳过偶数，再用 switch 区分不同选项。

## 5. 函数与接口

阅读 `src/basics/04_functions.c`、`src/basics/12_generic_variadic.c`。

函数声明包含返回类型、名字和参数类型；定义另包含函数体。采用 `int f(void)` 明确无参数。C 按值传参，修改调用者对象需要传递地址。数组参数会调整为指针，因此长度应单独传递。

递归必须有终止条件，并考虑调用深度与运算溢出。函数指针可用于回调。可变参数使用 `<stdarg.h>`，调用者必须遵守数量和类型协议；`float` 会提升为 `double`，窄整数经历整数提升。`_Generic` 按类型选择表达式，不是模板。

练习：编写求数组最大值的函数，明确空数组时的返回协议。

## 6. 数组与字符串

阅读 `src/basics/05_arrays_strings.c`。

数组是一组连续的同类型元素，索引从 0 开始，没有自动边界检查。数组不能直接整体赋值；多维数组是数组的数组。指定初始化可使用 `[index] = value`；部分初始化时，剩余元素进行零初始化。

字符串是以 `\0` 结束的字符序列。`strlen` 不计算终止符，`sizeof` 对字符数组计算整个对象大小。字符串字面量不可修改；`char text[] = "abc"` 创建可修改的副本。中文 UTF-8 文本占多个字节，`strlen` 计算字节数，不是可见字符数。

`strcmp` 比较内容，不能用指针的 `==` 代替。格式化写入检查 `snprintf` 的返回值，以识别错误或截断。

练习：遍历二维数组，用 `snprintf` 拼接字符串，并检测缓冲区过小的情况。

## 7. 指针与对象生命周期

阅读 `src/basics/06_pointers.c`。

### 7.1 指针是什么

指针对象保存一个对象的地址。`&object` 取得对象地址，`*pointer` 通过地址访问对象：

```c
int score = 80;
int *pointer = &score;
*pointer = 95; /* 修改 pointer 指向的 score。 */
```

`pointer` 和 `score` 是两个不同对象：前者保存地址，后者保存整数值。指针类型说明它指向何种对象，也决定解引用后的类型和指针运算的步长。例如 `int *` 加一会前进 `sizeof(int)` 个 C 字节，而不是固定前进一个字节。

### 7.2 声明读法与 const

读指针声明时，从变量名向外看 `*` 和限定符：

```c
const int *read_only;        /* 可改指向；不能通过它改所指 int。 */
int *const fixed = nullptr;  /* 不能改指向；可通过它改所指 int。 */
const int *const both = nullptr; /* 指向和所指 int 都不能通过此名修改。 */
```

记忆方法：`const` 修饰它左边的类型；若左边没有类型，则修饰右边。`const int *p` 中 `const` 修饰 `int`，`int *const p` 中 `const` 修饰指针 `p`。这只限制通过该表达式访问的修改方式，不会自动让底层对象变成只读，也不会阻止其他合法别名修改它。

### 7.3 数组和指针不同

数组是固定数量、连续存放的元素集合；指针是保存地址的独立对象。数组在大多数表达式中会转换为首元素指针，但在 `sizeof array` 和 `&array` 等情形不会按普通方式转换。函数形参写成数组也会调整为指针，所以长度要单独传入：

```c
int values[] = {10, 20, 30};
int *pointer = values; /* 通常等价于 &values[0]。 */
int (*whole_array_pointer)[3] = &values; /* 指向整个 int[3] 数组。 */
size_t count = sizeof values / sizeof values[0];

assert(values[1] == *(pointer + 1));
assert((*whole_array_pointer)[1] == 20);
assert(sizeof values == count * sizeof values[0]);
assert(sizeof pointer == sizeof(int *));
```

`values[1]` 的定义等价于 `*(values + 1)`；下标访问和指针访问是同一地址计算规则的两种写法。`int *pointer` 指向首个 `int`，而 `int (*whole_array_pointer)[3]` 指向整个 `int[3]`；`whole_array_pointer + 1` 会越过整个三元素数组。括号很重要：`int *p[3]` 是“含 3 个 int 指针的数组”，`int (*p)[3]` 才是“指向 3 个 int 数组的指针”。数组名通常不能重新赋值，指针变量可以改为指向别处。把数组传给函数后，形参已经是指针，`sizeof` 只能得到指针大小，不能恢复原数组长度。

### 7.4 指针运算和尾后指针

指针加减按元素大小移动。若 `p` 指向某个数组的元素，`p + n` 只有在仍指向该数组元素或恰好指向数组尾后一位时才有效。尾后指针可以用于循环结束比较、与数组内指针相减，**不能解引用**：

```c
int values[] = {4, 5, 6};
int *begin = values;
int *end = values + 3; /* 合法的尾后指针，不指向可读写元素。 */
ptrdiff_t length = end - begin; /* 同一数组内相减，结果类型是 ptrdiff_t。 */
```

相减的两个指针必须属于同一个数组（或刚好是它的尾后位置），且距离能由 `ptrdiff_t` 表示。指针排序比较也只应在同一数组范围内进行。不要用指针算术遍历不相关对象，不要解引用 `end`，也不要用 `void *` 做标准 C 指针算术。

### 7.5 空指针、未初始化指针和悬空指针

- **空指针**表示当前不指向对象。C23 可用 `nullptr` 表示；也可用标准宏 `NULL`。可以比较空指针，不能解引用。函数应明确说明参数能否为空，并在允许失败时检查它。
- **未初始化指针**含有不确定值。先赋有效对象地址或空指针，再读取它；不能先解引用或比较。
- **悬空指针**曾经有效，但对象生命周期已结束，例如局部变量所在函数返回，或动态内存已经 `free`。解引用它是未定义行为。

不要返回自动局部变量的地址：函数返回后局部对象生命周期结束，地址立即失效。需要把结果交给调用者时，使用输出参数，或分配由调用者负责释放的动态对象。把一个指针变量设为 `nullptr` 只清空这个变量，其他复制过地址的别名仍然悬空。

### 7.6 C23 `nullptr`、`NULL` 与整数 `0`

先区分两个概念：**空指针常量**是源码中用来表示“空”的表达式；它转换成某种指针类型后，得到该类型的**空指针值**。例如 `nullptr` 是空指针常量，赋给 `int *` 后，变量中保存的是 `int *` 类型的空指针值。空指针不指向任何对象或函数，不能解引用，但可以与其他空指针比较；它的底层位表示不要求全为零。

| 写法 | 是什么 | 要注意什么 |
| --- | --- | --- |
| `nullptr` | C23 关键字，类型为 `nullptr_t`，无需包含头文件 | 可初始化对象指针和函数指针；它本身不是指针，也不是整数，不能参与整数运算。 |
| `nullptr_t` | `<stddef.h>` 提供的类型，只有 `nullptr` 这一个值 | 适合需要明确保存或区分空指针常量类型的场合；普通指针变量通常不需要它。 |
| `NULL` | 标准库宏，如需使用可包含 `<stddef.h>` | 展开为哪种空指针常量由实现决定，不能假定它一定是 `0`、`(void *)0` 或 `nullptr`。 |
| `0` | 整数常量表达式，也可作为空指针常量 | `int zero = 0;` 中的 `zero` 是普通整数变量，不能直接当作空指针常量。 |
| `(void *)0` | C 中的空指针常量，表达式类型为 `void *` | 它与 `nullptr` 的类型不同；别把 C 的规则直接套用到 C++。 |

下面的例子展示赋值、比较和布尔判断。`if (pointer)` 为真表示指针非空；先确认非空，再解引用。

```c
#include <assert.h>
#include <stddef.h>

int main(void)
{
    int number = 7;
    int *pointer = nullptr;
    assert(pointer == nullptr);

    pointer = &number;
    if (pointer != nullptr) {
        assert(*pointer == 7);
    }

    nullptr_t empty = nullptr;
    int *another = empty;
    assert(empty == nullptr && another == nullptr);

    int *legacy = NULL;
    int *zero_literal = 0;
    assert(legacy == nullptr && zero_literal == nullptr);
    return 0;
}
```

`nullptr` 转为 `bool` 得到 `false`。不要写 `int value = nullptr;`：`nullptr_t` 不能转换为普通整数。也不要写 `int zero = 0; int *p = zero;`：**数值等于零**不代表表达式属于**整数常量表达式**。字符串终止符 `\0` 是另一概念；在 C 中字符常量 `'\0'` 恰好是值为零的整数常量，但不应用它表达指针为空。

`nullptr` 不会分配或释放内存；`pointer = nullptr` 只修改一个指针变量，其他别名仍保留原地址。若因此丢失动态分配对象的唯一地址，还会造成内存泄漏。输出指针时仍需按格式要求使用 `%p` 和 `(void *)pointer`，不能把 `nullptr` 直接传给期望 `void *` 的可变参数格式项。标准依据见 [WG14 C23 公开工作草案 N3220 的指针转换、`nullptr_t` 和 `<stddef.h>` 条款](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3220.pdf)。

### 7.7 指针参数、二级指针和所有权

C 按值传参。传入对象的地址，函数才能通过解引用修改调用者的对象；传入指针本身仍是按值复制。若函数要修改调用者保存的指针，需要传入指针的地址，即二级指针 `T **`：`*pointer_to_pointer` 是一级指针，`**pointer_to_pointer` 才是最终对象。

函数接口应说明指针参数是只读还是可写、是否允许为空、需要访问多少元素，以及是否转移所有权。借用指针不由当前函数释放；拥有动态内存的函数则要明确由谁调用 `free`。结构体指针用 `p->member` 访问成员，它等价于 `(*p).member`，并要求 `p` 指向有效结构体。动态分配细节见[动态内存](#10-动态内存)。

### 7.8 void 指针、函数指针和类型转换

`void *` 是通用对象指针，可在 C 中与其他对象指针相互转换；它没有元素类型，因此不能直接解引用或做标准指针算术。函数指针是另一类类型，不能假设可安全转换为 `void *`。函数指针示例见 `src/basics/06_pointers.c` 中的 `operation`。

不要把指针塞进 `int` 保存：整数和地址的宽度、表示方式可能不同。`uintptr_t` 仅在实现提供该可选类型时可用于特定往返转换场景，不能当作通用指针运算工具。输出对象地址用 `%p`，并将对象指针转换为 `void *`。

把任意地址强制转换为 `int *` 也不会让它自动有效：地址必须满足 `int` 的对齐要求，且该对象必须允许按 `int` 访问。读取网络数据或文件字节时，应按字节解析，或用 `memcpy` 复制到对齐且类型正确的对象，避免未对齐访问和违反有效类型/别名规则。

### 7.9 易错点速查

| 易混淆点 | 正确理解 |
| --- | --- |
| `p` 与 `*p` | `p` 是地址值；`*p` 是它指向的对象。只有 `p` 有效且指向活对象时才能解引用。 |
| `&array` 与 `array` | `array` 在多数表达式中变为首元素指针；`&array` 指向整个数组，类型不同，步长也不同。 |
| `sizeof(array)` 与 `sizeof(pointer)` | 前者得到整个数组占用大小；后者得到指针对象大小。数组传参后形参是指针。 |
| `const int *p` 与 `int *const p` | 前者限制通过 `p` 修改目标；后者限制 `p` 改指向。 |
| `p == q` 与 `*p == *q` | 前者比较地址；后者比较所指值，且需要两个指针都可解引用。 |
| 指针加一与字节加一 | `T *p + 1` 前进一个 `T` 元素；需要查看对象表示时使用 `unsigned char *`，并仍遵守对象边界。 |
| 设为空与释放对象 | `p = nullptr` 只清空变量，不释放动态内存，也不清理其他别名。动态对象需按所有权规则释放。 |

运行 `make build/basics/06_pointers` 后执行 `./build/basics/06_pointers`，查看交换、数组遍历、尾后指针、限定符、二级指针、`void *` 和函数指针的断言示例。

## 8. 自定义类型

阅读 `src/basics/07_aggregate_types.c`。

结构体、联合体和枚举都是用户定义类型的基础工具：`struct` 把多个成员组成一个对象，`union` 让多个成员共用一块存储，`enum` 给一组整数值起有意义的名字。它们只定义类型，不会自动创建变量；声明变量时才会产生对象。

### 8.1 结构体 `struct`

结构体的每个成员都有自己的存储空间，成员可以是标量、数组、指针，也可以是其他结构体。成员访问使用点号；通过指针访问时使用箭头：

```c
Person person = {.name = "小明", .age = 18, .location = {.x = 3, .y = 5}};
Person *pointer = &person;
person.location.x = 4;
pointer->age = 19; /* 等价于 (*pointer).age = 19。 */
```

指定初始化器 `.member = value` 按成员名赋值，不要求按声明顺序书写。没有指定的成员会按聚合初始化规则置零；嵌套结构体也可用嵌套的指定初始化器。指定的成员名必须存在，同一个成员不要重复指定。

结构体可以整体初始化和赋值，赋值会逐成员复制；C 不支持用 `==` 比较两个结构体，应按需要比较字段。若字段是指针，复制结构体只会复制地址，不会复制指针指向的内容，也不会转移或复制所有权。例如两个 `Person` 副本的 `name` 可能指向同一个字符串。若需要独立字符串，必须另外分配并复制其内容，同时明确谁负责释放。

编译器可能在成员之间或结构体末尾插入对齐填充，所以 `sizeof(struct)` 通常不等于成员大小之和。成员顺序可能影响总大小；可用 `<stddef.h>` 的 `offsetof(Type, member)` 查看本机成员偏移，用 `sizeof` 查看对象大小，但这些数值不是跨平台保证。结构体含填充字节时，直接用 `memcmp` 判断语义相等也不可靠，因为填充字节不一定有确定值。

### 8.2 联合体 `union`

联合体成员从同一块存储开始并相互重叠。它的大小足以存放最大成员，但也可能为满足对齐而包含额外空间。写入一个成员会把该成员的表示存入共享存储，并可能改变重叠成员的表示；普通教学代码应只读取最近写入的那个成员，不要把读取其他成员当作可移植的数值转换。

常见做法是使用“带标签的联合体”：在联合体旁放一个枚举，记录当前有效成员：

```c
typedef enum {
    INTEGER_VALUE,
    REAL_VALUE
} ValueKind;

typedef union {
    int integer;
    double real;
} ValueData;

typedef struct {
    ValueKind kind;
    ValueData data;
} Value;

Value value = {.kind = REAL_VALUE, .data.real = 3.5};
if (value.kind == REAL_VALUE) {
    printf("%.1f\n", value.data.real);
}
```

`kind` 和 `data` 是两个独立字段，编译器不会自动保证它们匹配。每次改变联合体成员时，也要同步改变标签；读取时先检查标签，再访问对应成员。C 对具有共同初始序列的结构体联合体成员提供了专门规则，但初学时应优先采用显式标签，避免依赖对象表示细节。

### 8.3 枚举 `enum` 与类型别名 `typedef`

未显式赋值时，第一个枚举项为 `0`，后续枚举项为前一项加 `1`；也可以显式指定值。枚举项名字是编译期常量，不是运行时字符串；打印文字时应使用 `switch` 或映射表。普通枚举的兼容整数类型和大小由实现决定，不应假定 `sizeof(enum)` 一定等于 `sizeof(int)`。外部输入转换成枚举后仍要检查是否属于程序支持的取值：

```c
typedef enum {
    STUDENT_ACTIVE = 1,
    STUDENT_GRADUATED = 3
} StudentStatus;
```

`typedef ExistingType Alias;` 为已有类型起别名，不会创建新对象，也不会自动产生与原类型不同的类型。`typedef struct Person { ... } Person;` 同时定义结构体标签 `struct Person` 和别名 `Person`；使用别名后，声明可写成 `Person person;`。`typedef` 不会改变成员布局、存储期或所有权。

### 8.4 复合字面量与扩展成员

`(Person){.name = "小红", .age = 21}` 是复合字面量，会创建一个未命名的对象，常用于就地构造结构体值。在函数体内它具有自动存储期，所在代码块结束后对象生命周期结束；不能把指向该对象的指针作为有效结果返回。文件作用域的复合字面量具有静态存储期。它是 C 的语法，不要和 C++ 的同名语法规则混为一谈。

位域可声明有限位宽的整数成员，例如标志位，但可取类型、位分配顺序、对齐和打包方式存在实现差异，且不能对位域取地址，因此不适合直接描述可移植的文件或网络格式。柔性数组成员写在结构体最后，例如 `unsigned char data[];`；柔性数组本身不贡献元素存储空间，`sizeof` 不包含它的元素（结构体末尾仍可能有对齐填充）。创建对象时要为额外元素分配足够内存并检查计算溢出。它适合紧凑的可变长对象，但初学时应先掌握固定长度数组和动态内存管理。

不要直接把结构体或联合体内存写入文件、网络或设备协议，并期待另一平台原样读回：填充、字节序、整数表示和对齐都可能不同。应逐字段编码成规定的字节序列。更多内存与二进制数据主题见 `docs/04_C语言进阶.md`。

练习：定义学生结构体和学生数组，用枚举表示状态；再用带标签的联合体表示“整数或小数”，确保每次读写都先维护并检查标签。运行示例时观察几种 `sizeof` 输出，并解释为什么它们不是语言保证的固定数字。

## 9. 作用域、存储期与链接

阅读 `src/basics/08_scope_storage.c`、`src/modules/`。

作用域决定哪里能使用名字，存储期决定对象存在多久，链接决定不同声明是否指同一实体。三者应分开理解。

普通局部对象有自动存储期；静态局部对象跨调用保存状态。文件作用域的 `static` 限制内部链接；公共函数及通常的文件作用域对象有外部链接，可用 `extern` 声明其他文件中的对象。动态分配对象具有分配存储期；`thread_local` 对象具有线程存储期。

### 9.1 `static` 的三种常见用法

`static` 的含义取决于声明所在的位置。先区分三个概念：**作用域**决定名字在哪里可见，**存储期**决定对象何时存在，**链接**决定不同声明是否指向同一个实体。

| 写法位置 | 主要效果 | 例子 |
| --- | --- | --- |
| 文件作用域的对象或函数 | 名字具有内部链接，只在当前翻译单元内可通过该名字访问；对象本来就有静态存储期。 | `static int module_count;` |
| 函数或代码块内的对象 | 对象具有静态存储期，整个程序运行期间保留；名字仍只在所在块内可见，且没有链接。 | `static int calls;` |
| 函数参数中的数组形参 | 声明调用者至少提供指定数量的可访问元素；形参仍会调整为指针。 | `int values[static 3]` |

#### 9.1.1 文件作用域：隐藏模块内部名字

在文件作用域声明对象或函数时，`static` 指定内部链接。它不会让该对象比文件作用域对象“活得更久”，因为文件作用域对象无论是否写 `static`，都具有静态存储期。

```c
static int module_count; /* 默认初始化为 0，静态存储期，内部链接。 */

static void reset_module(void)
{
    module_count = 0;
}
```

其他源文件不能通过外部链接直接引用 `module_count` 或 `reset_module`。这适合把实现细节留在 `.c` 文件中；需要共享的功能应通过头文件声明的公共函数接口访问。文件作用域的 `const` 在 C 中不会自动获得内部链接，需要时应明确写 `static const`。

#### 9.1.2 函数内：保留上一次调用的状态

局部 `static` 对象的名字仍是局部名字，但对象在整个程序运行期间存在。它只初始化一次；未显式初始化时为零。与普通局部变量不同，函数返回后它的值会保留：

```c
int next_id(void)
{
    static int next = 1;
    return next++;
}
```

连续调用 `next_id()` 会依次得到 `1`、`2`、`3`。记忆方法：**名字局部可见，数据全程留存**。`static` 不代表只读；要禁止修改还需使用 `const`。

静态存储期对象在程序启动前初始化，初始化值必须符合静态初始化规则，不能依赖每次调用才知道的参数或普通函数调用结果。递归调用会共用同一个局部静态对象；多个线程同时读写可变静态对象还需要同步，否则可能发生数据竞争。因此它不适合保存每次递归或每个线程各自独立的临时状态。

#### 9.1.3 数组形参：表达最小长度要求

```c
static void add_one_to_three(int values[static 3])
{
    for (int i = 0; i < 3; ++i) {
        values[i] += 1;
    }
}

int main(void)
{
    int values[3] = {10, 20, 30};
    add_one_to_three(values);
    return 0;
}
```

这里的 `static 3` 表示每次调用都必须传入一个至少有 3 个可访问元素的数组起始位置。这是调用约定，不会分配数组，也不会让 `values` 变成数组对象；函数形参会调整为 `int *`。编译器不一定能在所有调用点检查长度，调用者违反要求会导致未定义行为。函数内 `sizeof values` 得到的是指针大小，不是数组长度；需要长度时仍应显式传参。

#### 9.1.4 容易混淆的地方

- 文件作用域 `static` 主要影响**链接**；块作用域 `static` 主要体现为对象的**存储期**；数组形参里的 `static` 是**最小长度约定**。
- `static` 局部变量不会在每次函数调用时重置。需要每次调用独立状态时，使用普通局部变量或由调用者传入状态对象。
- 在头文件中定义 `static` 变量，会让每个包含该头文件的翻译单元各有一份独立对象。头文件中的 `static` 函数也可能在每个翻译单元各生成一份；短小的 `static inline` 函数可用于有意采用的头文件实现，其他情况通常放进 `.c` 文件。
- `static` 不是“编译期常量”标记。需要限制修改可加 `const`；需要 C23 编译期常量语义时应学习 `constexpr`，不要把它与 `static const` 混为一谈。

头文件放接口声明，源文件放实现，通过包含保护防止重复包含。不要在头文件中随意定义具有外部链接的普通对象或函数。

练习：给多文件示例添加减法接口，比较修改声明和修改实现导致的编译或链接错误。

## 10. 动态内存

阅读 `src/basics/09_dynamic_memory.c`。

`malloc` 分配未初始化的内存，`calloc` 将分配的字节清零，`realloc` 调整分配大小，`free` 释放。字节全零不能普遍当作所有类型的语义零值，如浮点数或空指针。

检查分配失败和大小乘法溢出。使用临时指针接收 `realloc`；失败时保留原分配，成功时停止使用旧指针。C23 下不要将零大小传给 `realloc`。

明确内存所有权，保证每个分配最终释放一次。释放后读取、重复释放、越界和遗漏释放都应避免。给一个指针赋空值不会修复其他悬空别名。

练习：实现动态整数数组，增加容量和失败处理。

## 11. 预处理与构建

阅读 `src/basics/10_preprocessor.c`。

`#include` 引入内容，`#define` 定义宏，`#undef` 取消宏，`#if/#ifdef/#ifndef/#elif/#else/#endif` 控制条件编译。`#` 可将宏参数字符串化，`##` 可拼接记号。宏不遵循普通函数调用规则，尤其要防止重复求值；计算逻辑优先用函数。

`__FILE__`、`__LINE__` 可用于定位信息；`__STDC_VERSION__` 表示实现声明的标准版本。`#error` 可拒绝不满足要求的配置，`#pragma` 常涉及实现相关行为。

练习：运行 `cc -std=c23 -E src/basics/10_preprocessor.c` 查看预处理结果。

## 12. 输入输出与错误处理

阅读 `src/basics/11_io_errors.c`。

`printf` 的格式必须匹配参数类型，`%zu` 用于 `size_t`，`%p` 配合 `void *`。读取文本优先使用限制长度的 `fgets`，再通过 `strtol` 等解析，并检查末尾指针、范围和 `errno`。不要将用户文本直接当作格式字符串。格式细节见[转义字符与输出格式](09_C转义字符与格式化输出.md)。

文件操作遵循打开、读写、定位、关闭的流程。检查返回值，用 `feof` 区分结束、`ferror` 判断错误；`fgetc` 的返回值应存入 `int` 才能区分字符与 `EOF`。不能用 `while (!feof(file))` 预测下一次读取是否成功。

`assert` 用于验证程序内部假设，不能替代输入或资源错误处理。普通错误通过返回状态、输出参数或错误对象向调用者传递。`main(int argc, char *argv[])` 可接收命令行参数。

练习：解析命令行中的整数，拒绝非法字符、超范围值及缺失参数。
