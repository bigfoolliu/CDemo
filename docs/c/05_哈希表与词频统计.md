# 哈希表（hash table）与词频统计（word frequency counting）

## 1. 目标与验收

从文本中统计 ASCII 英文单词的出现次数，学习哈希冲突、开放寻址、负载率、扩容与字符串所有权。可复用表位于 `src/common/word_map.h`；程序入口为 `src/advanced/07_word_frequency.c`。仅使用 ISO C 标准库。

| 编号 | 可观察结果 | 验证方式 | 状态 |
| --- | --- | --- | --- |
| AC-001 | 同槽不同词可独立计数，扩容后全部仍能查回 | 构造碰撞、250词反复扩容 | 通过 |
| AC-002 | 哈希表复制键，失败不破坏旧表 | 复用输入缓冲、注入键/槽分配失败、计数上限 | 通过 |
| AC-003 | 分词能跨读取块，大小写合并，报告稳定排序 | 5000字母长词、标点数字、空输入、平局 | 通过 |
| AC-004 | 默认无需输入，文件与stdin显式选择，构建调试可用 | 命令行、专项/整体检查与编译数据库 | 通过 |

## 2. 运行

在仓库根目录执行：

```sh
make word-frequency
./build/advanced/07_word_frequency --file README.md --top 15
printf 'Apple apple, PEAR!\n' | ./build/advanced/07_word_frequency --stdin
make test-word-frequency
make sanitize-word-frequency
make compile-commands
```

无参数时统计内置的17词短文，可被 `make run` 和 `make advanced` 自动执行，不等待终端输入。`--file 路径` 只读文件，`--stdin` 读取标准输入，两者互斥；`--top N` 为1..`SIZE_MAX`的严格十进制正整数。读取或输出失败会报错并以非零码退出，失败时不打印可能不完整的词频表。程序只输出到终端，不写日志或结果文件。

## 3. 分词规则与流式读取

按字节扫描，仅 ASCII `A..Z` 和 `a..z` 连续组成单词，并将大写字母转为小写。其他字节都是分隔符，因此 `C23` 变成 `c`，`don't` 变成 `don` 和 `t`。UTF-8非ASCII字节也按分隔符处理；这不是中文分词，也不完整支持国际化英文文本。

文件以4096字节块读取；当前单词保留在可扩容缓冲中，下一块可以继续拼接。到分隔符或输入结束才提交单词。缓冲按几何级数扩容，不设置任意词长上限；长度或内存不足时明确失败。成功提交后总词数才加一。最后一个词不需要以空格或换行结尾。

## 4. 哈希表如何存词

表使用64位FNV-1a哈希、二的幂次槽数与线性探测。对哈希取低位确定起始槽；槽被别的词占用时依次向后探测，回到数组开头继续。**哈希相同或起始槽相同不代表单词相同**，仍要比较长度与全部字节。一个实际碰撞不会覆盖原词。记录的“插入碰撞”是插入时最终槽与起始槽不同的次数，不是每次探测比较的总次数。

初始槽数为8。新增单词使负载率超过75%前，先把容量加倍并重新放置旧词；只移动键指针，不重新分配每个字符串。查询和单次插入在普通分布下通常很快，但哈希碰撞集中时探测可能退化到 O(n)；扩容本身是 O(n)。FNV-1a不是安全哈希，本教学实现不用于抗恶意碰撞的公开服务。

## 5. 所有权和失败行为

`word_map_increment` 接受非空 `a..z` 字节序列，可无NUL终止符。新词创建带NUL结尾的私有副本，调用者随即可以复用或释放输入缓冲；重复词只增加已有计数。调用者负责 `word_map_init` 和 `word_map_destroy`，不得浅复制含键指针的 `WordMap`。销毁后任何借用的键地址均失效；扩容后槽地址也会改变。单线程调用，不提供并发保护。

新增词先复制键，再尝试扩容；只在两个分配都成功后才提交。失败会释放临时键并保留原槽数组、容量、计数、键及碰撞次数。已有词达到 `UINT64_MAX` 时拒绝加一。测试通过可注入的分配/释放回调分别触发键复制和扩容失败，不需要耗尽机器内存。查询不存在或参数非法时不修改输出计数。

## 6. 排序与输出

报告先输出总词数、不同词数、槽数和插入碰撞，再按出现次数降序列出前N词。频率相同时按 ASCII 字典序排列，因此结果不受哈希槽遍历顺序影响。排序使用指向现有词条的临时指针数组，期间不修改哈希表；报告后释放数组。空输入输出零统计和零条目。

默认短文的期望结果：总词数17、不同词10，`c`出现4次；`care`、`is`、`learning`、`memory`各2次。`--top 3` 只显示 `c`、`care`、`is`。

## 7. 验证记录与练习

在macOS ARM64、Apple Clang 17、C23环境下，`make word-frequency` 输出总词数17、不同词10、初始8槽扩为16槽和3次插入碰撞。`make test-word-frequency`、`make sanitize-word-frequency`、`make sanitize`、整体 `make test` 与 `make lint` 均通过。核心测试覆盖碰撞、扩容后查询、输入缓冲复用、两处失败回滚、计数上限、跨块长词和词频平局排序。

命令行已验证内置文本、stdin、只读文件、空文件及非法选项。另使用固定随机种子生成40组二进制输入，逐项与独立的ASCII正则词频统计比较，计数与排序均一致。调试程序与 `make compile-commands` 已构建，数据库包含入口和测试。

练习：为哈希表增加删除操作，思考线性探测的“墓碑”如何避免查询提前停止；比较链地址法与当前开放寻址的所有权。增加Unicode分词前，先写清楚UTF-8解码、大小写折叠与“单词”边界定义，不要只把非ASCII字节当字母。
