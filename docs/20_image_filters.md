# 图像滤镜实验室：从像素到空间滤波

## 目标与验收

用纯C处理一张确定的合成图，比较均值模糊、Gaussian模糊、锐化、浮雕与Sobel边缘检测。无需外部图片、OpenCV或SDL。核心位于 `src/vision/image_filters.h/c`，入口为 `filters_demo.c`，复用现有画布与BMP导出。

| 编号 | 预期行为 | 验证方式 | 状态 |
| --- | --- | --- | --- |
| AC-001 | RGB转灰度，五种滤镜响应符合手算 | 颜色权重、恒定图、脉冲及斜坡测试 | 通过 |
| AC-002 | 边缘复制/零填充明确，核不翻转，允许原地处理 | 小图、非对称核及原地/分离输出对照 | 通过 |
| AC-003 | 非有限或非法输入不改输出，带符号响应在显示前保留 | 尺寸/枚举/NaN/溢出及显示限幅检查 | 通过 |
| AC-004 | 七张BMP保留已有文件，默认测试不写图片，构建/调试可用 | 导出与图像检查、专项/整体命令和配置核对 | 通过 |

## 运行与文件

在仓库根目录执行：

```sh
make filters                                 # 计算并导出七张BMP
./build/vision/filters_demo                   # 只打印每种滤镜响应范围
./build/vision/filters_demo --export --zero   # 改为零填充并导出
make test-filters                             # 不写文件的核心测试
make sanitize-filters                        # 地址与未定义行为检查
make filters-debug                           # 只构建调试入口
make compile-commands                        # 更新代码提示
```

图片保存到 `exports/filters-<效果>-<时间>-<序号>.bmp`，使用独占创建，重复运行保留已有图片。导出失败明确报错，已成功导出的图片保留。重复或未知参数报错且不产生新图片。

`make`、`make run`、`make test`、`make lint` 与 `make debug` 包含本例；普通运行只报告响应，不写文件。VS Code选择 **C: 图像滤镜实验室** 按F5，默认带 `--export`。本例不写日志文件，控制台报告可直接查看。

## 图像与内存

`VisionImage` 用固定容量 `double pixels[240][320]` 存放灰度或滤波响应，width/height限定实际有效区域，分别在1..320、1..240。坐标原点在左上角，x向右、y向下。未使用区域不参与计算。

双精度像素有意保留负值、小数和超过255的响应；不能在计算中直接使用uint8_t，否则容易截断、回绕或丢失导数方向。输入有效区域必须全部为有限数，输出也必须有限。

每次滤波在堆上分配约600KiB候选图，全部计算成功后复制到调用者输出，再释放临时缓冲。因此允许 `source == output`，且非法输入、分配失败或非有限运算不会部分修改结果。源和输出均由调用者拥有；演示中的大图使用静态存储，避免占用大量栈。时间复杂度为O(width×height×9)，Sobel计算两个核；暂不实现分离滤波优化。

## 灰度转换

```text
gray = (299*R + 587*G + 114*B) / 1000
```

保留小数，纯红、绿、蓝255分别转换为76.245、149.685、29.07，白色仍为255。此处是对RGB编码值的常见灰度近似，未做sRGB线性化，也不代表物理光亮度；alpha忽略。

演示图含渐变背景、贴边棋盘格、RGB色块、圆形、空心矩形与细线，便于观察亮度、平滑、边界及方向响应。五种滤镜分别读取同一份原始灰度图，不逐个叠加。

## 3×3核怎样工作

```text
response(x,y) = sum_ky,kx kernel[ky][kx] * source(x+kx-1,y+ky-1) + bias
```

核中心对齐当前像素，九个乘积相加。`vision_correlate3` 实现的是**互相关**：不翻转核。数学卷积需要将核旋转180度；对称模糊核两者相同，但Sobel或浮雕的响应方向会改变。API名称和非对称核测试明确保留这个区别。

边缘复制将越界坐标限制到最近边缘像素；零填充将越界采样视为0，不重新归一化边缘的有效系数。因此常量图在复制边界下保持亮度，而零填充会使模糊后的边缘变暗。例如3×3全90图的均值模糊：中心90，零填充角点40、边中点60。

## 五种滤镜

### 均值模糊

```text
1 1 1
1 1 1   × 1/9
1 1 1
```

九个像素等权平均，核系数和为1，平滑局部变化，同时模糊细节。

### Gaussian模糊

```text
1 2 1
2 4 2   × 1/16
1 2 1
```

采用常用3×3二项式Gaussian近似核，中心权重较大，系数和为1。它等于一维 `[1,2,1]/4` 在横纵方向的外积；本例仍直接使用二维九点计算，没有可配置sigma。

### 锐化

```text
 0 -1  0
-1  5 -1
 0 -1  0
```

增强中心与邻居的差异，常量图保持不变。会产生负值和超亮值，也可能放大噪声；代码保留这些响应直到显示阶段。

### 浮雕

```text
-2 -1  0
-1  0  1   + bias 128
 0  1  2
```

零和核强调左上与右下方向的亮度变化，128偏移把零响应映射到中灰。恒定图输出128，边缘呈现明暗立体感。这是方向滤镜，没有估计真实三维表面。

### Sobel边缘

```text
Gx:            Gy:
-1  0  1       -1 -2 -1
-2  0  2        0  0  0
-1  0  1        1  2  1
magnitude = hypot(Gx,Gy)
```

先保留两个带符号导数，再计算幅值。图像y向下，因此向下变亮对应正Gy。水平步长10的斜坡在中心得到Gx=80；反向斜坡得到-80，二者幅值都是80。幅值没有除以8归一化，可能超过255；显示限幅会丢失强边缘幅值差异。

这里没有Canny的非极大值抑制、双阈值与边缘连接，Sobel结果可能是较宽的亮边。

## 显示与七张图片

`vision_to_canvas` 将有限响应限制到0..255，再四舍五入并写入相等的RGB通道；小图未覆盖的画布区域填黑。不对每张图自动拉伸对比度，方便直接比较实际强度。

输出名称分别为 `filters-original`、`filters-grayscale`、`filters-box`、`filters-gaussian`、`filters-sharpen`、`filters-emboss`、`filters-sobel`。原图保留颜色，其他图为灰度。观察细线在模糊后变淡、锐化后的明暗增强、浮雕的方向感和Sobel的轮廓；使用 `--zero` 对照棋盘格贴边位置的变化。

在macOS ARM64、Apple Clang 17、C23上，`make test-filters`、`make sanitize-filters`、仓库整体 `make test` 与 `make lint` 均通过。`make filters-debug` 与 `make compile-commands` 通过，数据库包含核心、入口和测试。

七张BMP已检查尺寸、颜色与视觉效果；零填充的模糊角点比复制边界更暗。再次导出验证旧文件内容保持不变，默认运行及非法选项不创建图片。核心断言依据手算结果，而非复制实现逻辑；核心验证无需摄像头或图像库。
