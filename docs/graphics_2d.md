# 最小二维图形引擎

这个示例展示如何从像素数组构建图形和动画。纯 C 核心计算每个像素，SDL2 提供窗口、输入、计时和最终显示。它没有纹理素材、字体、透明混合、场景管理或 GPU 绘图接口。

## 运行与调试

需要支持本项目 C23 示例的编译器。窗口演示另需 SDL2 和 pkg-config，本机已安装 SDL2 2.32.6。缺少依赖时，macOS 可运行 `brew install sdl2 pkg-config`；其他平台需提供对应开发头文件和链接库。SDL 是第三方库，不能归为 ISO C 标准库。

```sh
make graphics                       # 构建并打开窗口
make graphics-build                 # 只构建窗口程序
make graphics-debug                 # 构建 -O0 -g3 调试版本
make compile-commands-graphics      # 生成包含 SDL 参数的完整编译数据库
make test-graphics                  # 无窗口核心断言，不依赖 SDL
make test-graphics-window           # SDL dummy 驱动验证显示与按键逻辑，需 SDL
make sanitize-graphics              # 地址与未定义行为检查
./build/graphics/demo --frames 120   # 绘制指定帧数后自动退出，便于显示验证
```

默认 `make` 不构建窗口；`make test`、`make lint` 包含纯 C 核心测试，不打开窗口或依赖 SDL。窗口源码的严格警告由 `graphics-build` 检查。`make clean` 清理图形程序和测试产物，保留用户文件。

在 VS Code 的“运行和调试”中选择 `C: 二维图形演示`，设置断点后按 F5。启动任务先生成图形编译数据库再构建调试版本。普通数据库生成会保留已生成的窗口记录；修改 SDL 编译参数后重新执行图形数据库任务。

| 操作 | 效果 |
| --- | --- |
| Space | 暂停或继续旋转 |
| N | 暂停时增加 0.75°，相当于按 60 帧/秒推进一次更新 |
| R | 将旋转角度归零，保留暂停状态 |
| Esc / 关闭窗口 | 释放资源并退出 |

窗口为 640×480，显示逻辑尺寸为 320×240 的画布，每个像素放大为 2×2 色块。界面左侧展示单点、直线、描边矩形、填充矩形和圆，右侧是绕红色中心点旋转的矩形；背景网格方便观察坐标和像素。

## 1. 像素缓冲区

`GfxCanvas` 持有 `pixels[240][320]`。原点在左上角，x 向右、y 向下，`pixels[y][x]` 表示一个像素。按连续内存观察，索引等价于 `y * 320 + x`。

颜色数值为 `0xFFRRGGBB`，`gfx_rgb` 用移位与按位或组合分量；`FF` 表示不透明。这里是整数数值格式，不是对不同平台字节排列的假设。SDL 的 `ARGB8888` 纹理与该数值格式匹配。清屏就是写满数组，所有绘图最终调用 `gfx_pixel`，由它忽略画布外坐标。

画布由调用者拥有，核心不分配内存、不保留指针，也不处理输入和时间。窗口示例用静态存储放置约 300 KiB 画布，避免占用较小的调用栈。所有传入的画布及输出地址必须有效。

## 2. 栅格化：把几何图形变成像素

`gfx_line` 使用 Bresenham 算法，累计理想直线与像素网格之间的误差。每一步比较误差，决定沿 x、y 或两个方向前进；不用除法计算斜率，水平、垂直和陡线都能处理，两个端点都包含在内。

矩形由左上角和像素宽高定义，右下角为 `(x + width - 1, y + height - 1)`。描边由四条线构成；填充扫描可见区域，避免对巨大但不可见的区域做无效循环。

`gfx_circle` 使用中点决策误差计算八分之一圆，再利用八向对称画完整圆周。它只画描边，半径零画一个点。第一版没有抗锯齿，放大后能直接看到栅格化的阶梯边缘。

接口将整数坐标和半径等参数限制在 ±16384 对应的范围内，以约束中间运算和循环数量；超出范围的请求忽略。矩形宽高非正、圆半径负数也忽略。部分位于画布外但参数合法的图形仍绘制可见像素。这是像素级裁切，不是完整的几何裁剪算法。核心通过静态断言要求 `int` 至少能表示 131072，本机 32 位 int 满足要求。

## 3. 二维变换：缩放、旋转、平移

矩形先以自身中心为原点定义四个局部顶点。对每个点，`gfx_transform_point` 按以下顺序计算：

```text
x = local_x * scale
y = local_y * scale
screen_x = x * cos(angle) - y * sin(angle) + translation_x
screen_y = x * sin(angle) + y * cos(angle) + translation_y
```

角度使用弧度，`π/2` 表示 90°。因为屏幕的 y 轴向下，正角度视觉上顺时针旋转。顺序很重要：先平移再旋转，会让物体绕屏幕原点公转。本例先绕局部原点旋转，再将中心放到 `(225, 130)`。

结果保留浮点精度，提交画线前用 `lround` 转为像素坐标。变换拒绝非有限输入和超范围结果，失败不改输出；零缩放产生同一点，负缩放表示反向缩放。第一版只提供均匀缩放，不引入矩阵系统。

## 4. 主循环与时间

每帧执行“处理所有事件 → 更新角度 → 清屏并绘制 → 显示”。旋转角速度为 45°/秒，角度增量为角速度乘 `dt`，避免直接按帧数决定运动速度。暂停期间仍读取时钟和显示；恢复时将当前增量清零，不累积暂停时间。

单帧 `dt` 上限为 0.1 秒，减少断点暂停或系统挂起后突然跳转。循环按约 60 帧/秒主动限速，不保证精确刷新率。按键自动重复被忽略；每次 N 按键仅在暂停时推进一次角度更新，断点暂停则是调试器暂停整个进程。

SDL 创建软件显示器和流式纹理，锁定后将像素逐行复制，使用返回的 `pitch` 计算行地址，不能假设纹理没有行填充。随后只将整张纹理提交到窗口，没有调用 SDL 画线或画圆。

## 推荐阅读和练习

先读 `graphics.h` 的接口契约，再读 `graphics.c` 的 `gfx_pixel → gfx_line → gfx_rect/gfx_circle`，再读 `demo.c` 的 `draw_scene → main`，最后读共享模块 `graphics_sdl.c` 的 `gfx_sdl_open → gfx_sdl_present → gfx_sdl_close`。推荐断点：像素写入、直线误差比较、圆对称绘制、点变换及每帧角度更新。

练习：改变直线端点观察八个方向；改变 scale 为 0.5、2 或 -1；给旋转矩形增加平移；观察半径为零和部分出界的圆。改动后运行核心测试和消毒器检查。

无窗口测试验证颜色、清屏、各向直线、端点、裁切、无效参数、圆对称及变换顺序。它验证数值和内存行为，窗口显示和按键操作还需实际运行确认。SDL 接口契约可查官方 [纹理锁定](https://wiki.libsdl.org/SDL2/SDL_LockTexture) 和 [事件轮询](https://wiki.libsdl.org/SDL2/SDL_PollEvent) 文档。

在此核心上继续学习 [粒子喷泉](particles.md)，观察固定步长、重力和对象池；两个演示共用 SDL 显示模块。
